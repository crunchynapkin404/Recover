# Phase 2b.4 redesign — session handoff

**Read this first if you are picking up the redesign.** Slice 0 of 10 shipped as
**v0.99.0** on 2026-08-12 and is live. Nine slices remain, each its own release.
One session per slice is the intended shape.

Authority order when documents disagree: **the code**, then `docs/ROADMAP.md`,
then this file. Everything here was true at v0.99.0; re-check before citing.

## What exists now, and what does not

`src/app/globals.css`; a seven-step type scale on a hard **12px floor**
(`--text-label` 12 · `--text-caption` 14 · `--text-body` 16 · `--text-title` 20

pinch-zoom restored; four guards; and the capture/audit tooling.

## Per-slice recipe

1. **Plan it** (`superpowers:writing-plans`) against the mockups. One plan per
   slice; do not pre-write later slices, their content depends on this one.
2. **Execute** with `superpowers:subagent-driven-development`: fresh implementer
   per task, task review after each, commit as you go.
3. **Verify in a browser.** `npm run verify:surfaces -- <slice>` then
   `npm run verify:axe -- <slice>`. **Open the PNGs.** A run that emits files is
   not evidence; a run whose files you looked at is.
4. **Whole-branch review at the end, on the most capable model.** Non-negotiable
   — see "The lesson that costs most to relearn".
5. **Release**: version bump, CHANGELOG written _from the diff_, roadmap updated
   (do **not** tick 2b.4 until slice 9), then `./scripts/release.sh <version> <pr>`.
   That script is not blocked — an old claim that `gh pr merge`/`gh release create`
   were classifier-refused was re-tested on 2026-08-12 and is dead.

## Environment traps, each of which has cost a run

- **Port 3000 is the LIVE PRODUCTION container** (`recover-app-1`, behind
  cloudflared). **Port 5434 is the LIVE database.** Never point anything at
  either. `scripts/verify-surfaces.ts` refuses both by design — do not weaken it.
- Dev server: `BETTER_AUTH_URL=http://localhost:3100
TRUSTED_ORIGINS=http://localhost:3100 npx next dev -p 3100`. Without the auth
  env, secure-cookie mode drops the session and every capture is a login page.
- Dev DB is `recover-devdb` on **5435**, which is what `.env` targets. A host
  restart stops it — check before blaming the app. Scripts need `DATABASE_URL`
  and `DATABASE_DRIVER=pg`.
- Seeded owner with real training data: `demo@recover.local` (password in
  `docs/axe-baseline-2026-08-11-seeded.md`). Must be an owner — `/admin` is a
  captured surface and redirects other roles.
- Browser: `CHROME_PATH=$HOME/.cache/ms-playwright/chromium_headless_shell-1234/chrome-headless-shell-linux64/chrome-headless-shell`
  with `LD_LIBRARY_PATH=$HOME/.cache/chromium-sysdeps/root/usr/lib/x86_64-linux-gnu:$HOME/.cache/chromium-sysdeps/root/lib/x86_64-linux-gnu`.
  If a `.so` is missing, `~/.cache/chromium-sysdeps/resolve.sh` fixes the chain
  unattended. Playwright lives only in the npx cache; only
  `~/.npm/_npx/e41f203b7505f1fb` matches revision 1234.
- Repeated capture runs accumulate revoked `screenshot-verify*` `api_tokens`
  rows in the dev DB. Harmless, but they inflate the settings surface and once
  made a headline diff mostly non-code. Clean them; leave real tokens alone.

## The guards, and the two you must re-pin

- `tests/contrast-guard.test.ts` — reads all six token blocks out of the shipped
  CSS and asserts every text ink clears **4.5:1** against every surface in
  **both** themes, worst-case; `--hairline` clears 3.0:1 and is barred from text.
- `tests/type-scale-guard.test.ts` — Tailwind utility scan, a syntax-agnostic
  raw-colour scan of `globals.css` outside the token blocks, an **AA floor on
  inline `style={{}}` text colour**, and an exact inventory that cannot grow.
- `tests/viewport-zoom-guard.test.ts` — neither pinch-zoom blocker can return.
- `tests/axe-report-split.test.ts` + `scripts/axe-split-proof.ts` — proof the
  confirmed/indeterminate split discriminates in both directions.

**The two `it.fails` ratchets are load-bearing.** They pin the current offender
counts (~395 arbitrary type sizes, ~583 ad-hoc ink lines) with two-sided bounds.
When your slice drives a number down, **re-pin the ceiling** — the suite will
tell you the actual figure. That re-pinning is the per-slice evidence that the
number moved. Lowering is routine; raising needs a reason in the commit message.

## Deliberately deferred, so nobody re-discovers it as a bug

- Light mode unreachable until slice 9 (`forcedTheme="dark"`,
  `enableColorScheme={false}`, static `themeColor`). All three lift in **one**
  commit — comments at each site say so.
- The axe pass is a local pre-merge step, **not CI**; its baseline is
  deliberately non-zero, so a zero-threshold gate would fail every PR until
  slice 9. `CONTRIBUTING.md` lists what would have to change.
- ~142 colour literals outside `style={{}}` (constant maps, chart `color=`
  props, SVG attributes) are unguarded. Slices migrate them surface by surface.
- `/activity/[id]` is not audited — it needs a seeded activity id, so it belongs
  to slice 6.
- `.tag-active` hardcodes the dark accent and does not follow the theme.

## The lesson that costs most to relearn

**Twenty-four commits of per-task review — each with a fresh implementer and an
independent reviewer — missed all five Criticals that one whole-branch review
then caught.** Every one was a seam or a scope question, invisible from inside a
single task: a guard reading only the first of six token blocks; a soundness
argument true for Tailwind utilities and false for inline styles; an exit gate
excluding real failures; a script defaulting to the live production container;
and a constraint nobody had ever tested against `main`. Budget the whole-branch
review as a gate, not a nicety.

The recurring shape underneath all of them: **a document outliving the code it
described.** The plan's prose was fixed and the code's default was not. A `curl`
check was specified that could never have worked. A pixel-diff was cited that
had been measured against the wrong baseline. Prefer guards that _derive_ from
the code — the contrast guard reads `globals.css` itself — over prose that
asserts what the code does.

Corollary, learned the same day: **a recorded capability limit needs re-testing
before it is cited.** A stale one silently hands work back to the owner forever.
