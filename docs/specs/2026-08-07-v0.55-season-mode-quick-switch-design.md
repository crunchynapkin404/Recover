# v0.55 Design: Season Mode Quick Switch

Date: 2026-08-07
Status: Draft (kickoff)

## Problem

Season mode and re-entry are already part of deterministic planning, but they are not directly controllable from Train. Athletes currently need a coach/tool round-trip to enter off-season, return to normal, or start re-entry.

## Goal

Expose season mode controls in Train so the athlete can switch between `normal`, `off_season`, and explicit `week_1` re-entry using existing planning update paths.

## Scope

- Show effective season state in Train week header.
- Add Train-native controls for:
  - `Normal`
  - `Off-season`
  - `Start re-entry`
- Reuse existing `update_training_plan` actions:
  - `set_season_mode`
  - `begin_reentry`
- Refresh Train after successful updates.

## Non-Goals

- No new season states.
- No change to off-season shaping rules.
- No change to rollover re-entry progression.
- No schema migration.

## UX Contract

- Train week header shows current season state.
- If athlete is in `normal`, `Normal` appears active and disabled.
- If athlete is in `off_season`, `Off-season` appears active and disabled.
- If athlete is in off-season and not already in re-entry, `Start re-entry` is available.
- If athlete is already in re-entry, the control shows the active stage label and does not offer a duplicate start action.

## Technical Contract

- Read state from existing effective planning fields.
- Write through existing plan update tool actions only.
- Revalidate `/train` and `/` on success.
- Preserve shared planning-surface effective-state contract.

## Acceptance Criteria

- Train week header displays effective season mode and re-entry stage.
- Athlete can switch to `normal` or `off_season` from Train.
- Athlete can start re-entry from Train when in off-season and not already re-entering.
- Full gate passes: format, typecheck, tests, build.

## Risks

- UI drift if Train reads raw constraints instead of effective fields.
- Duplicate or invalid re-entry action when stage is already active.

## Mitigations

- Bind UI to effective-state fields only.
- Gate `Start re-entry` on `effectiveSeasonMode === off_season` and `reentryStage === none`.
- Add focused action and component tests.

## Rollback

Revert Train season-mode UI/action wiring while keeping backend off-season support intact.
