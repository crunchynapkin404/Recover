# v0.48 Season Timeline (Target vs Actual) Spec

## Summary

Add a new Season view in the Train area that shows weekly target load versus weekly actual load, optimized for mobile first use. This view uses existing data only:

- week_plans.effective_target for weekly plan target
- activities.load for completed training load
- weeklyActivitySummaries and weeklyLoads in src/lib/charts.ts for weekly bucketing

## Scope

- Add a new Train tab: season (alongside week/history/fitness).
- Add a Season tab screen in /train that renders:
  - A compact mobile-first timeline chart for weekly target vs weekly actual load.
  - A short stat row: latest week target, latest week actual, season adherence percentage.
- Season window:
  - Source weeks from existing week_plans rows for the active plan.
  - Show up to last 16 weeks on mobile (horizontal scroll allowed), full available set on larger screens.
- Data rules:
  - Target load per week = week_plans.effective_target (null treated as unknown, not zero).
  - Actual load per week = summed activities.load in that Monday-based week.
  - Week matching key = weekStart (YYYY-MM-DD, Monday-based).
- Empty states:
  - No active plan: show setup-oriented empty state.
  - Active plan but no week_plans rows: show waiting state.
  - No activities in window: show actual as zero with explicit no sessions label.

## Non-Goals

- No new database columns or migrations.
- No forecast or future projected weeks.
- No replacement of Fitness charts (PMC and Weekly Load Bars stay unchanged).
- No coach logic changes.
- No changes to plan materialization/adaptation logic.

## UX and Mobile-First Behavior

- Tab is reachable in one tap from Train segmented control.
- Primary chart fits a phone viewport without requiring landscape mode.
- Visual grammar:
  - Target = line (or muted bars), Actual = contrasting line (or bars).
  - Delta cues only for current week and latest completed week to avoid clutter.
- Accessibility:
  - Chart container has a clear aria-label.
  - Stat values are visible as text (not chart-only meaning).

## Acceptance Criteria

1. Train segmented control includes season and keeps existing URL state behavior.
2. Opening /train?tab=season renders Season tab without affecting existing week/history/fitness.
3. Season timeline shows paired target/actual weekly values for active plan weeks.
4. Target values come from week_plans.effective_target only (no fallback to block target in UI).
5. Actual values come from activities.load weekly sums (Monday-based).
6. Mobile viewport (375px width) shows usable chart and stat row without layout break.
7. Empty states are explicit for no active plan and no timeline data.
8. Existing tests for log href and chart weekly helpers remain green; new season tests pass.

## Risks

- Historical rows may have null effective_target, creating sparse target lines.
- Week boundary mismatch if local day handling differs between week_plans and activities.
- Chart density on small screens can reduce readability for long plans.
- Querying all activities without date bounding can hurt performance.
