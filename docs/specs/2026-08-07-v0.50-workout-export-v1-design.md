# v0.50 - Workout Export v1 (.zwo first)

## Why this release exists

After v0.49 started breadth with fuelling, the next practical gap is workout
file export. Recover already holds deterministic planned sessions; this release
adds deterministic `.zwo` export for those sessions without introducing device
sync complexity.

## Product goal

Allow an athlete to export planned sessions as valid `.zwo` text files that
import in common trainers.

## Scope

### In scope

1. A pure exporter that converts a planned session into `.zwo` XML.
2. Batch export helper for a week's sessions (one file per session payload).
3. Deterministic mapping from session type/intensity/duration to ZWO blocks.
4. Tests that lock XML validity shape and deterministic output.

### Out of scope

1. No `.erg` or `.fit` in v0.50.
2. No direct device sync/integration push.
3. No schema changes or migrations.
4. No changes to planning/adaptation arithmetic.

## Data and mapping rules

Input session fields:

- sport
- type
- durationMins
- intensity
- description

Mapping principles:

1. Cycling sessions map to power-based ZWO blocks.
2. Non-cycling sessions are skipped with explicit reason (v1 constraint).
3. Duration always preserved to nearest minute split across deterministic block
   templates per type.
4. Unknown type degrades to a steady Endurance template.

## Acceptance criteria

1. Exporting identical session input produces byte-identical `.zwo` output.
2. Output contains required ZWO structure (`workout_file`, `name`, `workout`).
3. Endurance, Tempo, Intervals, Recovery, Brick have deterministic templates.
4. Unsupported sport returns a structured refusal, not malformed XML.
5. No DB migrations.

## Verification

1. Unit tests for mapping and determinism.
2. Contract tests for unsupported sport refusals.
3. Regression gates:
   - npm run lint
   - npm run typecheck
   - npm run test
   - npm run build
