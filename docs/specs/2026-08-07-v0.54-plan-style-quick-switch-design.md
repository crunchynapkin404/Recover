# v0.54 Design: Plan Style Quick Switch

Date: 2026-08-07
Status: Draft (kickoff)

## Problem

Plan style exists as a deterministic planning control, but athletes cannot switch it from the Train experience. Today, style changes depend on coach/tool interaction, adding friction and lowering discoverability.

## Goal

Expose a low-risk, in-product style switch on Train that lets athletes move between `balanced` and `block_lite` while preserving all existing planning behavior.

## Scope

- Display current effective style in Train week view.
- Add a style switch interaction with explicit user intent (confirmation copy).
- Reuse existing plan update path (`update_training_plan` action `set_style`).
- Refresh week state after a successful switch so users see immediate feedback.

## Non-Goals

- No algorithm changes in materialization or adaptation.
- No schema/database migration.
- No new planning styles.
- No race, taper, or off-season behavior change.

## UX Contract

- Week view shows a compact style status chip:
  - `Balanced`
  - `Block-lite`
- Action opens a small chooser with two options and one confirm action.
- Success state includes a short message that the style changed and the week refreshed.
- Failure path shows a concise error and leaves current style unchanged.

## Technical Contract

Single source of truth remains plan constraints:

- Read style from existing plan/week payload effective fields.
- Write style through existing update action + existing tool pathway.
- After write success, re-fetch/revalidate week data in server action path.

## Acceptance Criteria

- Train week view displays effective style from existing effective-state fields.
- User can change style from Train without using coach chat.
- After change, visible week data reflects updated style state.
- Existing planning tests show no algorithmic behavior drift.
- Full gate passes: format, typecheck, tests, build.

## Risks

- UI drift if Train reads raw constraints instead of effective fields.
- Stale UI if write success does not trigger refresh/revalidation.

## Mitigations

- Bind display to effective fields only.
- Keep write path inside existing update action boundary.
- Add focused tests around week view state and write action handling.

## Rollback

If regressions appear, rollback only the Train quick-switch UI/action wiring while keeping backend style support unchanged.
