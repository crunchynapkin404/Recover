# v0.57 Design — Deload week quick action

## Problem

Train week controls currently support easing, boosting, and skipping the open
week. Athletes who need a meaningful but non-zero reduction have to either run
multiple actions or leave Train to ask the coach/tools directly.

## Scope

Add one deterministic quick action, `deload_week`, to the Train week control and
existing update pathways.

## Non-goals

- No new schema fields.
- No changes to week materialization or adaptation algorithms.
- No race-aware taper logic.

## User-facing behavior

- Train week control shows: Ease week, Deload week, Boost week, Skip week.
- Deload applies to the posted `weekNumber` (open `skeletonWeek` wiring remains
  the caller responsibility from Train page).
- Deload sets the week `targetLoadTotal` to 50% of current value, rounded to
  nearest integer.
- Notes record explicit provenance:
  `deload_week: train quick week deload`.

## Action-layer behavior

- `setWeekAdjustmentQuick` accepts `deload_week` in `weekAction`.
- `setWeekAdjustmentQuick` maps action reason to
  `train quick week deload`.
- `update_training_plan` tool action enum includes `deload_week`.
- Existing validation invariants remain:
  - week-level actions require `weekNumber` and `reason`
  - day-level move/swap rules unchanged

## Verification

- Train switch render test includes Deload button and hidden action value.
- Train switch form coverage confirms `weekNumber` appears once per action.
- Plan action test verifies deload writes the expected note and target load.
- Tool registry test validates `deload_week` enum acceptance.
- Frozen tool surface snapshot updates for enum expansion.
