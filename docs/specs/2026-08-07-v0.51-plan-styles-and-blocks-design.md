# v0.51 - Plan styles and blocks

## Why this release exists

After v0.49 (fuelling) and v0.50 (workout export), breadth now moves to how a
week feels without changing safety math. Athletes want a planning style that
matches preference (evenly spread vs light concentration) while preserving all
existing safeguards and determinism.

## Product goal

Introduce a selectable, deterministic plan style with two options:

1. balanced (default, backward-compatible)
2. block_lite (new)

Style should change legal ordering preferences only, never readiness safety,
adaptation precedence, or no-training-lost accounting.

## Scope

### In scope

1. Style selection at plan level using existing plan constraints.
2. Deterministic style-aware ordering preferences in week materialization.
3. Effective style surfaced in plan/week payloads and tool responses.
4. Regression coverage proving unchanged safety precedence and accounting paths.

### Out of scope

1. No stochastic search and no LLM-dependent planning core.
2. No rewrite of macro periodization math.
3. No changes to readiness scoring, thresholds, or adaptation arithmetic.
4. No changes to actual-load derivation and booking semantics.
5. No workout execution or export format expansion.

## Style semantics

## balanced

Intent:

- preserve current weekly rhythm and spread stress through the week.

Deterministic behavior:

1. Preserve current placement behavior unless a tie-break is required.
2. Prefer wider spacing between key sessions.
3. Preserve existing no-consecutive-quality constraints.
4. Tie-break by day ascending, then block index ascending.

## block_lite

Intent:

- concentrate one weekly focus stimulus lightly, then absorb.

Deterministic behavior:

1. Focus stimulus derived from phase plus week parity:
   - base: aerobic emphasis
   - build: threshold-focused and vo2-focused alternating by week parity
   - peak: race-specific key stimulus first
   - recovery and taper: reduced density, no extra concentration
2. Prefer front-half placement for focus sessions when legal.
3. Prefer back-half placement for support and recovery sessions.
4. If concentration conflicts with legal placement, fall back to balanced for
   that decision.

## Hard invariants (must not regress)

1. Race-day and locked-day invariants hold first.
2. Availability legality and slot admission rules hold first.
3. Readiness adaptation precedence and final fit-to-availability hold first.
4. No-training-lost actual booking behavior is unchanged.
5. Style is a tie-break layer only after safety and legality.

## Data model and compatibility

1. Reuse existing training-plan constraints payload.
2. Add optional constraints.planStyle with values:
   - balanced
   - block_lite
3. Missing or invalid planStyle resolves to balanced.
4. No schema migration required.

## Determinism contract

1. Identical inputs plus balanced yield identical outputs.
2. Identical inputs plus block_lite yield identical outputs.
3. Balanced remains behavior-compatible with pre-v0.51 plans.
4. Style can change ordering and template preference only, never safety
   predicates.

## Acceptance criteria

1. Existing plans without planStyle behave as balanced with no drift.
2. block_lite changes ordering pattern only in eligible legal weeks.
3. Safety outcomes for red, amber, and calibrating states are unchanged.
4. No-training-lost tests pass unchanged.
5. Effective style is visible in responses used by UI and tools.
6. Lint, typecheck, test, and build pass.

## Verification matrix

1. Unit tests:
   - style resolver default and invalid handling
   - balanced and block_lite ordering determinism
   - tie-break stability
2. Integration tests:
   - adaptation precedence unchanged under both styles
   - illegal placements rejected before style preferences apply
3. Regression tests:
   - no-training-lost path unchanged
   - balanced output parity fixtures vs pre-v0.51 baseline
4. Contract tests:
   - effectiveStyle surfaced in plan and week payloads

## Rollout and guardrails

1. Keep balanced default for all existing plans.
2. Expose style selector for new/edited plans once tests are green.
3. Add a kill-switch to force balanced globally if needed.
4. Track fallback frequency from block_lite to balanced decisions.
5. Run deterministic rerun checks in CI for both styles.

## Non-goal guardrail

If a proposal requires randomization, unsourced heuristics without explicit
bounds, or changes to readiness/adaptation arithmetic, it is out of scope for
v0.51 and must be deferred.
