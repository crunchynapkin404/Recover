# v0.52 - Off-season mode

## Why this release exists

Athletes need a maintenance mode between race-focused blocks that preserves
habit and health without carrying full in-season intensity density.

## Product goal

Add an explicit off-season mode that:

1. Reduces quality-session density deterministically.
2. Requires explicit staged re-entry before normal structure returns.
3. Preserves existing safety precedence and legality checks.

## Scope

### In scope

1. Plan constraints carry `seasonMode` and `reentryStage`.
2. Week materialization applies deterministic off-season shaping.
3. Rollover advances re-entry stage (`week_1` -> `week_2` -> `none`).
4. Tools expose and allow updating mode/state.

### Out of scope

1. New readiness metrics or threshold changes.
2. New periodization macro math.
3. Stochastic template selection.
4. Multi-A-race bridge logic (v0.53).

## Behavior contract

1. `seasonMode = normal` preserves current behavior.
2. `seasonMode = off_season`:
   - At most one quality session per week.
   - Additional quality sessions downgrade to endurance.
   - Session target reduces by one, with floor at three.
3. Re-entry:
   - `week_1`: no intervals, max one quality session.
   - `week_2`: max two quality sessions.
   - Next rollover clears to `none`.

## Hard invariants

1. Race-day replacement logic remains authoritative.
2. Slot legality/admission remains authoritative.
3. Readiness and illness safety adaptation precedence remains unchanged.
4. Determinism: identical input state produces identical output.

## Acceptance criteria

1. Mode/state defaults are backward-compatible (`normal` + `none`).
2. Off-season weeks reduce quality density as specified.
3. Explicit re-entry progression is observable and deterministic.
4. Tool/API surfaces return effective mode/state.
5. Lint, typecheck, tests, and build pass.
