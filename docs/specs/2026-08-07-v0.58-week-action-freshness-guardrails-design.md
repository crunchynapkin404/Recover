# v0.58 Design — Week action freshness guardrails

## Problem

Train week quick actions are posted with a hidden `weekNumber` captured at page
render time. If the athlete leaves the page open across a week rollover,
submitting an old form can target a week that is no longer the open week.

## Scope

Add a deterministic open-week freshness guard in the Train week quick action
server action.

## Non-goals

- No schema changes.
- No week materialization or adaptation logic changes.
- No new action types.

## Behavior

- Parse and validate `weekAction` and `weekNumber` exactly as before.
- Read current open week via `getOpenWeekPlan(userId)`.
- If open week is missing or `weekNumber !== openWeek.skeletonWeek`, return:
  `{ ok: false, error: "stale_week_adjustment" }`.
- If matched, continue existing action execution path unchanged.

## Determinism and safety

- Guard uses only explicit posted week and current open week state.
- Stale submissions perform no writes.
- Fresh submissions preserve existing semantics:
  - `reduce_load` = 70%
  - `deload_week` = 50%
  - `increase_load` = 110%
  - `skip_week` = 0

## Verification

- Action test verifies stale mismatch returns `stale_week_adjustment`.
- Action test verifies no target load mutation on stale submission.
- Existing quick-action success tests remain green.
