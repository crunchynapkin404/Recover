# v0.99 slice 1 — Today, three states

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Redesign Today onto the v0.99 token system and make it state-aware — the block that answers the athlete's current moment leads, and the rest keep their place below.

**Architecture:** A pure state selector (`src/lib/today/state.ts`) resolves one of three states from three inputs — local time, when the last session ended, and whether the athlete has self-reported today. `page.tsx` fetches the same data it already fetches (plus two cheap reads), computes the state, and renders the existing block components in a state-specific order. Three new presentational blocks (`just-landed-card`, `day-log-card`, `bedtime-card`) render data the app already computes. Every Today component migrates from hardcoded pixel sizes and `text-white/N` alphas to the slice-0 token utilities.

**Tech Stack:** Next 16.2.10 App Router with Turbopack (server components), Tailwind v4 with `@theme inline` tokens, Drizzle/Postgres, Vitest + `react-dom/server` `renderToString` for component tests, Playwright (`scripts/verify-surfaces.ts`) for browser verification.

## Global Constraints

Every task's requirements implicitly include this section.

**Design authority.** `docs/design/v0.99-today.html` (open from disk; it has a theme toggle). Build against the mockup, not against spec prose. Tokens are defined in `src/app/globals.css` — that file is the source of truth, the mockup only copies it.

**The 12px floor.** `--text-label` (0.75rem / 12px) is the smallest type that may exist. Nothing renders smaller, in any component, at any breakpoint.

**No new figure.** Every number rendered must already be computed and displayed somewhere in the app today. A redesign is exactly where a number appears to make a card look balanced; it does not happen here. If a block looks empty, it stays empty.

**No IA change.** Nav stays Today/Train/Coach/Body/Menu. Every route keeps its path. No new routes.

**Reorder, never hide.** The mockup's per-state order list is the _lead_ sequence. Blocks it does not name still render, below the lead blocks, in their morning order. No state may make content unreachable that another state shows. (Decision taken 2026-08-12; the mockup's abbreviated phone frames illustrate the lead, not an exhaustive block list. The spec agrees: "same blocks, same numbers — the block that answers the moment comes first and the rest keep their place below.")

**Light mode stays unreachable.** `forcedTheme="dark"` and `enableColorScheme={false}` in `theme-provider.tsx` do not move in this slice — they lift in one commit in slice 9. Build both themes correctly anyway; the contrast guard and the axe pass both check light.

**The ratchets — re-pin in the same commit that moves them.** `tests/type-scale-guard.test.ts` holds `OFFENDER_CEILINGS` with two-sided bounds (`RATCHET_SLACK = 25`). Every task that removes offenders makes those counts drop, and past 25 the slack bound goes red.

**Every task that touches a component ends with the ceilings re-pinned**, in that task's own commit:

```bash
npx vitest run tests/type-scale-guard.test.ts 2>&1 | grep -A2 "Re-pin OFFENDER_CEILINGS"
```

Read the two actual counts out of the failure message and write them into `OFFENDER_CEILINGS`. Never compute your own number. A ceiling may only go **down** — if one rose, you added offenders; fix the component, not the ceiling.

This is deliberately per-task rather than once at the end. Leaving the suite red for ten commits would mean no task could use "the suite is green" as its gate, which is exactly how a real regression rides along unnoticed. The re-pin is two numbers and it is the per-slice evidence the guard asks for.

The two `it.fails` assertions stay failing-as-designed throughout — they pass only at zero offenders, which is slice 9. That is not a red suite; `it.fails` failing is a pass.

**Testing.** Component tests use `renderToString` from `react-dom/server` in the default node environment — see `src/components/today/vitals-grid.test.tsx` for the house pattern. No jsdom, no testing-library. Assert on rendered output and token class names, not on implementation details.

**React 19 splits adjacent JSX children with `<!-- -->`** (found while executing Task 1). Any two sibling children in the same element — text next to an expression, or two expressions — render with an HTML comment between them, so `{hoursDone.toFixed(1)}h` comes out as `5.8<!-- -->h` and `{m.label} {m.value}` as `Recovery<!-- --> <!-- -->82`. `src/components/body/body-battery.test.tsx` is the house convention (`"30<!-- -->%"`).

**Where a test string in this plan crosses such a boundary, adapt it** — either assert the real output including the marker, or assert on the smallest substring that does not span the boundary. Adapt **only** for this rendering artifact. Never relax an assertion because the behaviour it checks is failing: if a test fails for any reason other than `<!-- -->` placement, the component is wrong, not the test.

**This is Next.js 16.2.10 with Turbopack, not Next 15** (also found in Task 1). Compiled CSS lands in `.next/static/chunks/*.css`, **not** `.next/static/css/*.css`. Any command in this plan that greps build output uses the chunks path.

### Task 2: The Today state selector

**Files:**

- Create: `src/lib/today/state.ts`
- Create: `src/lib/today/state.test.ts`

**Interfaces:**

- Consumes: nothing.
- Produces, for Task 11:
  - `type TodayState = "morning" | "post-session" | "evening"`
  - `EVENING_HOUR: number` (18)
  - `POST_SESSION_WINDOW_MS: number`
  - `interface TodayStateInput { now: Date; lastSessionEndedAt: Date | null; hasDayLog: boolean }`
  - `resolveTodayState(input: TodayStateInput): TodayState`
  - `interface DayLogFields { energy1_10: number | null; soreness1_10: number | null; stress1_10: number | null; notes: string | null; tags: string[] | null }`
  - `hasDayLog(row: DayLogFields | null | undefined): boolean`
  - `previewStateFrom(param: string | undefined): TodayState | null`

**The rule, and why each clause is there.** Three inputs, checked in this order:

1. **evening** — local hour ≥ 18 **and** the athlete has self-reported today. Both halves are needed: 18:00 alone would make the post-session state unreachable for anyone who trains after work, and a log alone says nothing about the time.
2. **post-session** — the most recent session ended within the last 4 hours. Measured from the session's **end**, not its start: a three-hour ride starting at 15:00 has only just finished at 18:00.
3. **morning** — everything else. The default, so a missing input can only ever produce the state that was there before this slice.

This produces both non-morning mockups exactly (18:47 with a fresh ride and no log yet → post-session; 21:52 with the day logged → evening), and it has no midnight cliff: a ride that ends at 23:30 still leads at 00:15 because the window is elapsed time, never a calendar-day comparison.

/**
 * Which moment Today leads with (v0.99 slice 1).
 *
 * Same route, same blocks, same numbers — only the order changes. The
 * blocks a state does not lead with still render below it, so no state can
 * make anything unreachable.
 */
export type TodayState = "morning" | "post-session" | "evening";

/** Local hour from which the day is closing rather than starting. */
export const EVENING_HOUR = 18;

/**
 * How long after a session ends Today keeps leading with it. Elapsed time,
 * deliberately not "landed today" — a calendar-day test puts a cliff at
 * midnight, where a ride that ended twenty minutes ago would stop being the
 * thing the athlete opened the app to see.
 */
export const POST_SESSION_WINDOW_MS = 4 * 60 * 60 * 1000;

export interface TodayStateInput {
  /** Now, in the athlete's local timezone (the container's TZ). */
  now: Date;
  /**
   * When the most recent session ENDED, or null when none is recent. End,
   * not start: a three-hour ride starting at 15:00 has only just finished
   * at 18:00, and a window measured from the start would already be half
   * spent before the athlete got off the bike.
   */
  lastSessionEndedAt: Date | null;
  /** Whether the athlete has self-reported today. See hasDayLog below. */
  hasDayLog: boolean;
}

export function resolveTodayState({
  now,
  lastSessionEndedAt,
  hasDayLog,
}: TodayStateInput): TodayState {
  // Both halves are load-bearing. The hour alone would make post-session
  // unreachable for anyone who trains after work; the log alone says
  // nothing about where in the day the athlete is.
  if (now.getHours() >= EVENING_HOUR && hasDayLog) return "evening";

  if (lastSessionEndedAt != null) {
    const elapsed = now.getTime() - lastSessionEndedAt.getTime();
    // elapsed >= 0 rejects a future-dated session: clock skew or a
    // mis-stored timestamp must not make a ride that has not happened
    // read as one that just landed.
    if (elapsed >= 0 && elapsed <= POST_SESSION_WINDOW_MS)
      return "post-session";
  }

  // The default is the state Today was in before this slice, so any missing
  // or unreadable input degrades to the behaviour that already shipped.
  return "morning";
}

/** The self-reported columns of a `wellness_daily` row. */
export interface DayLogFields {
  energy1_10: number | null;
  soreness1_10: number | null;
  stress1_10: number | null;
  notes: string | null;
  tags: string[] | null;
}

/**
 * Whether the athlete actually logged the day.
 *
 * NOT "a wellness row exists". The intervals.icu wellness endpoint emits a
 * row for every calendar day back to account creation, most of them empty,
 * so row existence is evidence of nothing. Only a field the athlete could
 * have typed counts — and a zero counts, because 0 stress is an answer.
 */
export function hasDayLog(row: DayLogFields | null | undefined): boolean {
  if (!row) return false;
  return (
    row.energy1_10 != null ||
    row.soreness1_10 != null ||
    row.stress1_10 != null ||
    (row.notes != null && row.notes.trim() !== "") ||
    (row.tags != null && row.tags.length > 0)
  );
}

const STATES: readonly TodayState[] = ["morning", "post-session", "evening"];

/**
 * `?state=` override, for screenshots and local design work.
 *
 * Hard-gated to non-production: the capture script has to be able to reach
 * all three states on demand, and a real athlete must never be able to
 * reorder their own Today by typing a query string. Reordering is all it
 * can do — no data is faked, so a state with nothing to lead on simply
 * shows an honestly empty lead.
 */
export function previewStateFrom(param: string | undefined): TodayState | null {
  if (process.env.NODE_ENV === "production") return null;
  if (param == null) return null;
  return STATES.includes(param as TodayState) ? (param as TodayState) : null;
}

  const h = Math.floor(hours);
  const m = Math.round((hours - h) * 60);
  return `${h}:${String(m).padStart(2, "0")}`;
}

/** TSB to one decimal with a real minus sign: -1.94 → "−1.9". */
export function fmtTsb(tsb: number): string {

  if (why.tsb != null) parts.push(`TSB ${fmtTsb(why.tsb)}`);

interface Props {

  slot: DaySlot | null;

/**

  adjustmentReason,

  heading = "Today's session",
  variant = "full",
  allowMarkDone = true,

          ✓ Done
        </span>
      </section>

      <div className="mb-3 flex items-center justify-between">
        <span className="text-label font-bold uppercase tracking-[0.14em] text-ink-muted">
          {heading}
        </span>
        {workouts.length === 1 && (
          <span className={pill}>{workouts[0].intensity}</span>
        )}

              )}
            </div>
            {w.description && (
              <p className="mt-1 text-caption text-ink-secondary">
                {w.description}
              </p>
            )}
          </div>
        ))
      ) : (
        <p className="text-title font-bold text-ink-muted">Rest</p>
      )}

        <div data-adjustment className="mt-3 rounded-xl bg-surface-overlay p-2">
          <p className="text-caption leading-snug text-chart-3">
            ↻ {adjustmentReason}
          </p>
        </div>
      )}

      {workouts.length > 0 &&
        (slot.status === "completed" ? (
          <p className="mt-3 border-t border-hairline pt-3 text-label font-bold text-chart-2">
            ✓ Done
          </p>

/**
 * Read-only sibling of getOrFetchActivityDetail: returns whatever is
 * already cached and NEVER calls intervals.icu.
 *
 * Today renders on every app open, and its post-session block exists
 * precisely because the athlete has not opened /activity/[id] — so the
 * cache is cold exactly when the block appears. Fetching here would put a
 * third-party call and a write burst on the app's most-loaded surface. A
 * cold cache simply means no stream minis; the block's CTA warms it on the
 * destination page, where the wait is expected.
 */
export async function getCachedActivityDetail(
  userId: string,
  activityId: string
): Promise<ActivityDetail | null> {
  if (!UUID.test(activityId)) return null;

  const activity = await db.query.activities.findFirst({
    where: and(
      eq(schema.activities.id, activityId),
      eq(schema.activities.userId, userId)
    ),
  });
  if (!activity) return null;

  const cached = await db.query.activityStreams.findMany({
    where: eq(schema.activityStreams.activityId, activity.id),
  });
  if (cached.length === 0)
    return { activity, streams: null, laps: null, reason: "unavailable" };

  return fromRows(activity, cached);
}

  label: string;
  value: string;
  unit?: string;
}

export interface JustLandedStream {
  label: string;
  /** Already a path — see downsample + sparkPath. "" is filtered by the caller. */
  path: string;
  /** Tailwind stroke utility, e.g. "stroke-chart-5". */
  className: string;
}

export interface JustLandedProps {
  activityId: string;
  name: string;
  /** "Cycling · Tue Aug 11 · intervals.icu" */
  meta: string;
  /** What the plan asked for, or null when this ride was unplanned. */
  asked: string | null;
  /** What the activity actually recorded. */
  delivered: string;
  stats: JustLandedStat[];
  debrief: {
    answer: string | null;
    notes: string | null;
    review: string | null;
  } | null;
  /** Empty when the stream cache is cold — the strip is then omitted. */
  streams: JustLandedStream[];
  lapCount: number | null;
}

/**
 * A ride stream is thousands of points. Handing one straight to sparkPath
 * emits a path string longer than the page, and spreads the whole array
 * into Math.min/Math.max, which throws RangeError past roughly 100k
 * arguments. Bucket first, average within the bucket, and keep a bucket
 * with no real readings honestly null.
 */
export function downsample(
  values: (number | null)[],
  buckets = 40
): (number | null)[] {
  if (values.length <= buckets) return values;
  const size = values.length / buckets;
  const out: (number | null)[] = [];
  for (let i = 0; i < buckets; i++) {
    const slice = values.slice(
      Math.floor(i * size),
      Math.floor((i + 1) * size)
    );
    const nums = slice.filter((v): v is number => v != null);
    out.push(
      nums.length > 0 ? nums.reduce((s, v) => s + v, 0) / nums.length : null
    );
  }
  return out;
}

/** Convenience for the page: stream values → a drawable path, or "". */
export function streamPath(values: (number | null)[] | undefined): string {
  if (!values || values.length === 0) return "";
  return sparkPath(downsample(values));
}

export function DayLogCard({ scores, tags, notes, debriefLine }: DayLogProps) {

      <p className="text-label font-bold uppercase tracking-[0.14em] text-ink-muted">

        <div className="mt-3 grid grid-cols-3 gap-2">
          {scores.map((s) => (
            <div
              key={s.label}
              className="rounded-xl border border-hairline bg-surface-overlay px-3 py-2.5 text-center"
            >

              </p>
              <p className="mt-1 text-label font-bold uppercase tracking-[0.14em] text-ink-muted">

              </p>
            </div>
          ))}
        </div>
      )}

      {tags.length > 0 && (
        <p className="mt-3 text-caption text-ink-secondary">

        </p>
      )}

      {notes != null && notes.trim() !== "" && (

```tsx
import type { SleepDebtResult } from "@/lib/sleep-debt";
import { ConfidenceChip } from "@/components/ui/confidence-chip";

interface Props {
  /** "22:45" from sleepDebtFrom; null when it has no anchor to compute one. */
  bedtime: string | null;
  debtSecs: number | null;
  /** Wider than Confidence: sleepDebtFrom can also say "none". */
  confidence: SleepDebtResult["confidence"];
}

/**
 * Sleep debt is a 14-night cumulative deficit, so it routinely runs to
 * hours. Minutes stay minutes while they read naturally; past 90 it
 * switches to hours rather than printing "debt 1359m".
 */
function fmtDebt(debtSecs: number): string {
  const mins = Math.round(debtSecs / 60);
  if (mins < 90) return `debt ${mins}m`;
  return `debt ${(mins / 60).toFixed(1)}h · 14d`;
}

/**
 * The evening's closing block (v0.99 slice 1): tonight's bed-by target.
 *
 * `bedtime` is a field sleepDebtFrom already returns and Today already
 * computes — this block is a placement, not a new figure. No bedtime means
 * the model has no anchor for one (fewer than MIN_BEDTIME_SAMPLES real
 * bed-starts and no wake-time fallback), and the honest answer is silence.
 */
export function BedtimeCard({ bedtime, debtSecs, confidence }: Props) {
  if (!bedtime) return null;
  const debt = debtSecs != null && debtSecs > 0 ? fmtDebt(debtSecs) : null;

  return (
    <section className="flex items-center justify-between gap-4 rounded-[20px] border border-hairline bg-surface-raised p-4">
      <span className="font-numeric text-figure font-bold leading-none text-chart-1">
        {bedtime}
      </span>
      <span className="max-w-[60%] text-right text-caption text-ink-secondary">
        Bed by, to hold tonight&apos;s payback inside what one night can repay
        {debt && ` · ${debt}`}
        {confidence === "low" && (
          <span className="ml-1.5 inline-block align-middle">
            <ConfidenceChip level="low" />
          </span>
        )}
      </span>
    </section>
  );
}

        "coach",
        "calibration",

    };

    ));

    // The 7fr/5fr split is a morning-shaped layout — vitals and the

    // cannot survive an arbitrary reorder, and desktop is not where
    // the post-session moment happens, so the other two states take
    // one honest column instead of a wrong two.
    if (todayState !== "morning")
      return <div className="min-w-0">{ordered}</div>;

    const left = new Set(["heroFull", "calibration", "vitals", "week"]);
    return (
      <div className="lg:grid lg:grid-cols-[7fr_5fr] lg:items-start lg:gap-5">
        <div className="min-w-0">
          {ordered.filter((n) =>
            left.has(String((n as React.ReactElement).key))
          )}
        </div>
        <div className="min-w-0">
          {ordered.filter(
            (n) => !left.has(String((n as React.ReactElement).key))
          )}
        </div>
      </div>
    );
  })();
}
```
