# v0.99 Slice 4 — Coach — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`
> (recommended) or `superpowers:executing-plans` to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the Coach surface onto the v0.99 token system and the 12px type
floor, and close the capture gap that has meant only its empty state was ever
measured.

**Architecture:** Coach is three components (~1,030 lines) behind a single route,
whose interesting states are all reachable only by query string or by click.
Tasks 1–2 make those states _visible to the tooling_ and capture a pre-migration
baseline; tasks 3–8 migrate the surface; tasks 9–12 test, re-pin, verify in a
browser, and release. The capture work comes first on purpose: it is the
evidence that the migration changed something.

**Tech Stack:** Next.js 15 (App Router, RSC), Tailwind v4 (`@theme inline`
tokens in `src/app/globals.css`), Drizzle + Postgres, Vitest, Playwright
(`chromium_headless_shell-1234`), axe-core.

## What the investigation established (do not re-derive)

**Coach is a multi-state surface behind one URL**, and `SURFACES` in
`scripts/verify-surfaces.ts` maps `coach → /coach` only. `/coach` renders
`ChatInterface` with `initialThreadId = null`, so `messages.length === 0` and
the component returns its empty state. Everything below has therefore **never
been screenshotted or axe-audited in the project's history**:

| State                    | Reached by                | Components exercised                                                       |
| ------------------------ | ------------------------- | -------------------------------------------------------------------------- |
| Thread with messages     | `/coach?thread=<uuid>`    | message bubbles, timestamp, `ArtifactCard`, typing indicator, error banner |
| Mobile History sheet     | `/coach?history=1`        | `HistorySheet` → `BottomSheet` + `HistoryPanel`                            |
| Desktop History dropdown | click on the title button | `HistoryPanel` in `.menu-pop`                                              |
| Unconfigured             | no `llm_settings` row     | the "needs an LLM key" card                                                |

This is the same shape as slice 3's Body finding (`body → /body` captured only
the Trends tab; adding the other three found 26 confirmed violations on a
surface previously reported at zero).

**Measured offender counts** (2026-08-13, `main` at `7c8a4e4`), across
`src/app/coach/*.tsx`, `src/components/coach/*.tsx`, `src/components/ui/bottom-sheet.tsx`:

- **26** arbitrary type sizes (`text-[…px]`) — project total 137
- **46** ad-hoc white/black alphas — project total 311
- **16** instances **below the 12px floor**, enumerated in Task 4/6/7/8 below

**The seed creates no inbox threads.** `scripts/seed-demo.ts` inserts exactly one
`chat_threads` row and never sets `kind`, so it defaults to `"chat"`.
`listInboxItems()` reads only `INBOX_THREAD_KINDS`
(`morning`/`weekly`/`debrief`/`monthly`), so it returns `[]` and the History
panel's "From your coach" section renders its empty state. All five
`KIND_STYLE` tiles — the richest colour grammar on the surface, and the one
place Coach uses inline `style={{ color }}` — are unreachable in any capture.

**`InboxKind` has five values; the DB enum has four.** `"warning"` is not a
thread kind — it is a `morning` thread whose assistant message carries
`toolCalls.warning`. `listInboxItems` derives it at
`src/lib/coach-inbox.ts:114-117`. Seeding all five tiles therefore needs **two**
morning threads.

- [ ] **Step 3: Implement `seedDemoInbox`**

```ts
/**
 * Five inbox items, one per InboxKind the History panel styles. Without these
 * the "From your coach" section renders its empty state and all five
 * KIND_STYLE tiles are unreachable — including in the capture script, which
 * is why the tiles' colours went unaudited until slice 4.
 *
 * `warning` is not a thread kind: it is a `morning` thread whose assistant
 * message carries toolCalls.warning (see coach-inbox.ts:114-117).
 */
export async function seedDemoInbox(userId: string) {
  const existing = await db.query.chatThreads.findFirst({
    where: and(
      eq(schema.chatThreads.userId, userId),
      inArray(schema.chatThreads.kind, [
        "morning",
        "weekly",
        "debrief",
        "monthly",
      ])
    ),
  });
  if (existing) return;

  const day = 86_400_000;
  const now = Date.now();

  const specs: {
    kind: "morning" | "weekly" | "debrief" | "monthly";
    title: string | null;
    content: string;
    ageMs: number;
    warning?: string;
    unread?: boolean;
  }[] = [
    {
      kind: "morning",
      title: null,
      content:
        "**Readiness 71 (amber).** HRV 48 ms is a touch under your 30-day " +
        "median, sleep was 7.1 h. Keep today's endurance ride, hold the low " +
        "end of zone 2, and we'll reassess before Thursday's intervals.",
      ageMs: 2 * 3600_000,
      unread: true,
    },
    {
      kind: "debrief",
      title: "Ride debrief — Tempo along the Vecht",
      content:
        "92 minutes at 198 W normalised, 84 TSS. Your last 20 minutes held " +
        "power with heart rate drifting 4 bpm — that is a clean aerobic " +
        "signature, not a fade.",
      ageMs: 1 * day,
    },
    {
      kind: "weekly",
      title: null,
      content:
        "Seven hours across five sessions, 412 TSS — 8% over the planned " +
        "week and your third straight build. Next week steps down before it " +
        "steps up again.",
      ageMs: 3 * day,
    },
    {
      kind: "morning",
      title: null,
      content:
        "HRV has sat below your baseline for four consecutive mornings while " +
        "load kept climbing. Treat today as easy or off; this is the pattern " +
        "that precedes a stall.",
      ageMs: 5 * day,
      warning: "hrv_suppressed",
    },
    {
      kind: "monthly",
      title: null,
      content:
        "July: 28 hours, 1,640 TSS, CTL from 52 to 61. Threshold power up " +
        "6 W. The consistency is doing more work than any single session.",
      ageMs: 12 * day,
    },
  ];

  for (const spec of specs) {
    const createdAt = new Date(now - spec.ageMs);
    const [thread] = await db
      .insert(schema.chatThreads)
      .values({
        userId,
        kind: spec.kind,
        title: spec.title,
        createdAt,
        updatedAt: createdAt,
      })
      .returning();

    await db.insert(schema.chatMessages).values({
      threadId: thread.id,
      role: "assistant",
      content: spec.content,
      createdAt,
      // readAt null = unread. Only the newest item is left unread so the
      // badge renders "· 1" rather than a number that changes per seed run.
      readAt: spec.unread ? null : createdAt,
      ...(spec.warning ? { toolCalls: { warning: spec.warning } } : {}),
    });
  }
}
```

- [ ] **Step 2: Write the resolver**

Add above `main()`:

```ts
/**
 * The seeded chat thread's id is a uuid, so `/coach?thread=…` cannot live in
 * SURFACES as a literal. Read it off the History panel's own first chat link.
 *
 * Throws rather than returning null: a missing thread link means the seed did
 * not run, and silently dropping the surface would restore exactly the blind
 * spot this slice exists to close.
 */
async function resolveCoachThreadPath(page: Page): Promise<string> {
  await page.goto(`${BASE_URL}/coach?history=1`, {
    waitUntil: "networkidle",
    timeout: 20_000,
  });
  const href = await page
    .locator('a[href^="/coach?thread="]')
    .first()
    .getAttribute("href", { timeout: 10_000 });
  if (!href) {
    throw new Error(
      "no /coach?thread= link on /coach?history=1 — run scripts/seed-demo.ts " +
        "against the dev DB (5435) first. Refusing to skip: an uncaptured " +
        "thread is the blind spot slice 4 closes."
    );
  }
  return href;
}
```

### Task 7: The message list — and the timestamp that was never a timestamp

**A real defect, found while planning.** Line 531-536 renders

```tsx

}
```

inside `messages.map`. That is the **render time**, evaluated fresh for every
message on every render — not the message's time. Every bubble in a thread shows
