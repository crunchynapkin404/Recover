# v0.99 slice 2 — Train, at the floor

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the whole Train surface — four tabs, 22 components and a 1,537-line page — on the v0.99 token system at the 12px floor, taking the four structural cuts the mockup's decision table requires because the floor does not otherwise fit.

**Architecture:** No new routes, no new data, no page split. One foundations task adds the two things the surface needs that do not exist yet (a race ink token, and the removal of the competing 10px floor in `.label-micro`), then each subsequent task migrates one coherent group of components with its own tests and its own ratchet re-pin. Four of those tasks also carry a structural change the decision table names: the week day row loses its spelled-out status pill for the dot-plus-`sr-only` convention `week-strip.tsx` already uses, the next-week preview collapses to one summary row that expands on demand, the season timeline drops 24 per-bar micro-labels for an axis tick every third week plus one detail readout, and the fitness tiles drop the repeated category word the chart's own legend states once.

**Tech Stack:** Next 16.2.10 App Router with Turbopack (server components), Tailwind v4 with `@theme inline` tokens, Drizzle/Postgres, Vitest + `react-dom/server` `renderToString` for component tests, Playwright (`scripts/verify-surfaces.ts`) for browser verification.

### The ink buckets are the nearest-value partition — and the one override that beats them

**Why the cut sits between `/60` and `/55`, and must stay there.** `text-white/N` is a dark-only artefact (light mode is unreachable until slice 9), so the only question is what each alpha renders as in dark and which token is nearest. Over `--surface-raised` `#161616` — which is also what `.glass` composites to over `--surface-base` — `--ink-secondary` `#b4b4b4` is 180 and `--ink-muted` `#8a8a8a` is 138, so the midpoint is **159**:

| alpha | renders | Δ secondary | Δ muted | nearest   |
| ----- | ------- | ----------- | ------- | --------- |
| `/70` | 185     | 5           | 47      | secondary |
| `/65` | 173     | 7           | 35      | secondary |
| `/60` | 162     | 18          | 24      | secondary |
| `/55` | 150     | 30          | 12      | muted     |
| `/50` | 139     | 41          | 1       | muted     |

The table above is exactly this partition. It is not a guess.

**A global redraw was proposed and rejected** (2026-08-13). The proposal moved `/65` and `/60` down into `ink-muted`, on the argument that the widest gap _inside_ a bucket (`/80` → `/60`) collapses to identical ink while the narrowest gap in the range (`/60` → `/55`) survives across a token change. Two things defeated it:

1. **The arithmetic.** `/65` sits 7 from secondary and 35 from muted. Moving it is a five-fold fidelity loss.
2. **The argument proves too much.** "Widest intra-bucket gap collapses, narrowest cross-bucket gap survives" is a property of _every_ boundary in a quantization, including the proposed one — `/85` → `/70` is a 15-point collapse and `/70` → `/65` a 5-point survivor. Relocating a cut relocates the artefact; it cannot remove it. Three ink steps cannot carry six alphas, wherever the boundary goes.

**The real defect, and the governing rule.** Tasks 5, 6 and 7 each independently reported the same thing, and none of them was about the boundary: a **pair inside one component** — a label and its subordinate detail — that differed by alpha landed on the same token, and a deliberate hierarchy went flat. fuelling-card's Before/During/After labels vs its body copy; the skeleton table's week-number cell vs its phase and target cells; block-sheet's label vs its help text.

> **The per-pair override.** Where a component renders a label and a subordinate detail that differed by alpha, the quieter one goes to **`ink-muted`**, even where nearest-value would put it on `ink-secondary`. Nearest-value is the default; local hierarchy is the override. One principle plus one explicit exception — never a fudged boundary _and_ an exception.

This is safe by construction: `--ink-muted` is the text floor and clears 4.5:1 against every surface in both themes, so the override can never introduce a contrast failure.

Fourteen sites across the six files migrated in Tasks 3–7 carried `/60` or `/65`. They are swept in **Task 12** rather than by reopening six commits.

**Colour literals in TS, not just utilities.** Train passes hex strings as props (`FitnessTile.color`, `railColor()` in `history-list.tsx`, `BAND_COLOR` in the header chip). These are part of the ~142 unguarded literals the handoff records. ## Task 1: The race ink token, and the second 10px floor

Train is the first slice to touch a `.label-micro` call site, and the mockup's decision table hands that class to whoever gets here first. It is also the surface that renders race day, currently as a literal `text-fuchsia-300` with no token behind it.

**Why `--ink-race` and not `--race`:** `roleOfToken()` in `src/lib/design/tokens.ts` derives a token's role **from its name** — `/(?:^|-)ink(?:-|$)/` returns `"text"`. A token named `ink-race` therefore self-registers with `tests/contrast-guard.test.ts` and is asserted at 4.5:1 against every surface in both themes with no guard edit at all. A token named `race` would return `null` and fail the build asking to be given a role. Let the mechanism do the work.

**The values, measured not guessed** (worst case across `--surface-base/-raised/-overlay`, and across glass composited on both grounds):

| ----- | --------- | ----------- | -------- | ------------------------------------------------------------------------------------- |

| dark  | `#f0abfc` | 9.37:1      | 9.04:1   | fuchsia-300 — **the exact hex shipping today**, so dark's rendered pixels do not move |

Add to `tests/type-scale-guard.test.ts`, inside the `describe` that already holds the `globals.css` scan:

```ts
/**
 * The floor is a property of the app, not of Tailwind. `.label-micro`
 * hardcoded `font-size: 10px` right through slices 0 and 1 — a second,
 * uncoordinated floor that no utility scan could see, backing labels on
 * seven surfaces. This reads every font-size declaration in the file,
 * resolves the ones written as tokens, and holds them all to 12px.
 */
it("declares no font-size below the 12px floor in globals.css", () => {
  const css = readFileSync(CSS_PATH, "utf8");
  const SCALE_PX: Record<string, number> = {
    "--text-label": 12,
    "--text-caption": 14,
    "--text-body": 16,
    "--text-title": 20,
    "--text-heading": 24,
    "--text-figure": 30,
    "--text-hero": 44,
  };
  const found: string[] = [];
  for (const m of css.matchAll(/^\s*font-size:\s*([^;]+);/gm)) {
    const raw = m[1].trim();
    const line = css.slice(0, m.index).split("\n").length;
    const tokenMatch = /^var\((--text-[a-z]+)\)$/.exec(raw);
    const px = tokenMatch
      ? SCALE_PX[tokenMatch[1]]
      : /^([\d.]+)px$/.test(raw)
        ? Number(/^([\d.]+)px$/.exec(raw)![1])
        : /^([\d.]+)rem$/.test(raw)
          ? Number(/^([\d.]+)rem$/.exec(raw)![1]) * 16
          : null;
    if (px == null) {
      found.push(`globals.css:${line} — unresolvable font-size: ${raw}`);
    } else if (px < 12) {
      found.push(
        `globals.css:${line} — font-size: ${raw} (${px}px) is below the floor`
      );
    }
  }
  expect(found, found.join("\n")).toEqual([]);
});
```

```tsx
import type { DaySlot } from "@/lib/week-plan/types";
import { plannedMins, availableMins } from "@/lib/week-plan/fill";

/**
 * Next week, collapsed to one row (v0.99 slice 2).
 *
 * Seven more full day rows — each provisional, each with its own badge —
 * roughly doubled the scroll length of the app's most-visited tab for data
 * that is a forecast, not a commitment. This is the demotion: the summary
 * is always visible, the days are one tap away, and nothing is removed.
 * Committed data (this week) is untouched and stays fully expanded.
 *
 * A native <details> rather than the base-ui Collapsible: this renders
 * inside a server component, and the disclosure needs no JavaScript to
 * work. races-section.tsx already uses the same element twice.
 *
 * Every figure here is computed by the same producers page.tsx calls for
 * the note beneath the list, so the two can never disagree.
 */
export function NextWeekSummary({
  days,
  pinned,
  targetHours,
  children,
}: {
  days: DaySlot[];
  pinned: Record<string, boolean>;
  targetHours: number | null;
  children: React.ReactNode;
}) {
  const sessions = days.filter((d) => d.workouts.length > 0).length;
  // "Open" is a day the calendar offers time on that has nothing planned —
  // the actionable half of the summary, and the reason to tap through.
  const open = days.filter(
    (d) => d.workouts.length === 0 && d.availableMins > 0
  ).length;
  const plannedHours = plannedMins(days) / 60;
  const provisional = days.some((d) => !pinned[d.date]);

  return (
    <div className="border-b border-hairline last:border-0">
      <div className="px-4 py-2 text-center text-label font-bold uppercase tracking-[0.2em] text-ink-muted">
        Next week
      </div>
      <details className="group">
        <summary className="cursor-pointer list-none px-4 py-3 text-caption text-ink-secondary">
          {provisional && (
            <span aria-hidden className="mr-1.5 text-ink-muted">
              ~
            </span>
          )}
          <span className="sr-only">{provisional ? "Provisional: " : ""}</span>
          {`${sessions} session${sessions === 1 ? "" : "s"} planned, ${open} open · ${plannedHours.toFixed(1)}h planned`}
          {/* `> 0`, not just non-null: a zero target is the absence of one,
              and "of 0h target" reads as a claim about the plan rather than
              as a missing value. */}
          {targetHours != null &&
            targetHours > 0 &&
            ` of ${targetHours}h target`}
          <span className="mt-1 block text-label font-bold text-accent">
            {`Show all ${days.length} days${provisional ? " (provisional)" : ""} →`}
          </span>
        </summary>
        {children}
      </details>
    </div>
  );
}
```
