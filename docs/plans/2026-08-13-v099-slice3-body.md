# v0.99 slice 3 — Body, at the floor

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the whole Body surface — four tabs, 14 components and an 839-line page — on the v0.99 token system at the 12px floor, taking the three editorial decisions the floor and the duplicate-data rule force, and making the three tabs nobody has ever captured capturable.

**Architecture:** No new routes, no new data, no page split. One task makes the surface visible to the capture script, one migrates the page chrome, then each subsequent task migrates one coherent group of components with its own tests and its own ratchet re-pin. Three tasks carry a structural change: `BaselineTrendCard` trades two raw colour-string props for one `tone` prop resolved to chart tokens, `JournalForm` loses the second page header that printed the athlete's streak a second time, and Labs' two always-open entry forms fold behind the `Collapsible` primitive the journal already uses.

**Tech Stack:** Next 16.2.10 App Router with Turbopack (server components), Tailwind v4 with `@theme inline` tokens, Drizzle/Postgres, Vitest + `react-dom/server` `renderToString` for component tests, Playwright (`scripts/verify-surfaces.ts`) for browser verification.

## Global Constraints

Every task's requirements implicitly include this section.

**Design authority.** There is no Body mockup, and none is being made. `docs/design/README.md` is explicit that the two committed references settle "the type scale, the ink ramp and the density questions that are expensive to re-decide nine times", and that "everything below that level is each slice's own call, made against the real components with the screenshot and axe passes". So: take the **system** from `docs/design/v0.99-train.html` (open it from disk, it has a theme toggle) and the **shipped vocabulary** from what slices 1 and 2 actually built — `src/components/train/train-tabs.tsx`, `src/app/train/page.tsx`'s `TrainHeader`, `src/components/ui/empty-state.tsx`. Tokens live in `src/app/globals.css`; that file is the source of truth.

**Cards are `.glass`.** Same as slice 2, for the same reason (v0.100.1 reversed slice 0's flat-surface decision on owner feedback). A Body card currently written `rounded-[18px] border border-white/[0.08] bg-white/[0.03]` becomes `glass rounded-[18px]` — `.glass` supplies both the fill and the 1px border, so the `border-*` and `bg-*` utilities are **removed**, not translated. Eight of Body's blocks are already `glass rounded-[2rem]`; leave that radius alone, it is not this slice's business.

**The 12px floor.** `--text-label` (0.75rem / 12px) is the smallest type that may exist. Nothing renders smaller, in any component, at any breakpoint. Body ships **75 arbitrary type sizes and 161 ad-hoc ink utilities**, and its smallest text is 8px (`journal-form.tsx`'s streak ring readout, which this slice deletes, and `sleep-history-strip.tsx`'s weekday initial, which it does not).

**No new figure.** Every number rendered must already be computed and displayed somewhere in the app today. If a block looks empty, it stays empty.

**No IA change, no page split, and no change to the Trends stack.** Nav stays Today/Train/Coach/Body/Menu. Every route keeps its path. The four tab bodies stay inside `src/app/body/page.tsx`. **Owner decision, 2026-08-13: the Trends tab keeps one full-width card per metric, stacked.** Folding the optional metrics behind a disclosure and laying them out as a 2-up grid were both offered and both declined; this slice moves Body onto the token scale and does not restructure that list. Record no roadmap line for it — it was decided, not deferred.

**Light mode stays unreachable.** `forcedTheme="dark"` and `enableColorScheme={false}` in `theme-provider.tsx` do not move in this slice — they lift in one commit in slice 9. Build both themes correctly anyway; the contrast guard and the axe pass both check light. **Body in light mode today is the single best argument for this slice**: open `.screenshots/slice3-before/body-light-phone.png` before starting. The tabs, the range pills, every card eyebrow and every current reading are white-on-white and unreadable, and axe scored that surface **0 confirmed findings** because `color-contrast` resolves as _indeterminate_ over the gradient ground. The capture is committed to nothing — regenerate it with the Task 1 command if it is missing.

`text-primary-foreground` is the ink **on** accent. Alphas on a **token** (`bg-accent/10`, `border-accent/30`) are legal and invisible to the ratchet — only `white`/`black` alphas are offenders.

### The ink buckets are the nearest-value partition, and the one override that beats them

Slice 2 settled this and it is not reopened here. `text-white/N` is a dark-only artefact (light mode is unreachable until slice 9), so the only question is what each alpha renders as in dark and which token is nearest. Over `--surface-raised` `#161616` — which is also what `.glass` composites to over `--surface-base` — `--ink-secondary` `#b4b4b4` is 180 and `--ink-muted` `#8a8a8a` is 138, so the midpoint is **159**: `/70`→185, `/65`→173, `/60`→162 are all nearer secondary; `/55`→150 and `/50`→139 are nearer muted. The table above is exactly that partition, not a guess. A global redraw of the boundary was proposed and rejected on 2026-08-13; relocating a cut relocates the artefact, it cannot remove it.

> **The per-pair override.** Where a component renders a label and a subordinate detail that differed by alpha, the quieter one goes to **`ink-muted`**, even where nearest-value would put it on `ink-secondary`. Nearest-value is the default; local hierarchy is the override.

This is safe by construction: `--ink-muted` is the text floor and clears 4.5:1 against every surface in both themes, so the override can never introduce a contrast failure. Body's live instances of the pair: `milestones-card.tsx`'s row label (`/70`) vs its detail (`/40`); `biomarker-list.tsx`'s marker name (`/80`) vs its unit (`/40`); `bio-age-card.tsx`'s component label (`/50`) vs its offset.

**Colour literals in TS, not just utilities.** Body passes hex strings as props and in constant maps: `BaselineTrendCard`'s `color`/`bandFill` at 16 call sites, `STAGES` in `sleep-night-card.tsx`, `SEGMENTS` in `sleep-history-strip.tsx`, the `energy-grad` stops in `body-battery.tsx`, `BAND_COLOR` in `blood-pressure-card.tsx`. These are part of the ~142 unguarded literals the handoff records and this slice migrates all of them to `var(--chart-N)` strings or to tone classes.

**`INLINE_COLOR_INVENTORY` does not change in this slice.** Body's three entries are `background: s.color` — values assembled at runtime, which the scan records as unreadable regardless of what `s.color` holds. Swapping `"#3b82f6"` for `"var(--chart-1)"` inside the constant leaves the entry byte-identical. Do **not** edit the inventory to "reflect" the migration; if the assertion fires, something really did change and that is the finding.

```tsx
import Link from "next/link";
import { BODY_TABS, type BodyTab } from "@/lib/log-href";

const LABEL: Record<BodyTab, string> = {
  trends: "Trends",
  sleep: "Sleep",
  journal: "Journal",
  labs: "Labs",
};

/**
 * Body's segmented control. Links, not state — every segment carries the rest
 * of the filter state with it (see buildBodyHref), so the browser's back
 * button walks the athlete's actual path. Deliberately identical in treatment
 * to TrainTabs: two sibling surfaces whose tab rows looked alike by accident
 * and drifted apart by accident too.
 */
export function BodyTabs({
  active,
  href,
}: {
  active: BodyTab;
  href: (over: { tab?: BodyTab }) => string;
}) {
  return (
    <nav aria-label="Body sections" className="flex flex-wrap gap-1.5">
      {BODY_TABS.map((t) => (
        <Link
          key={t}
          href={href({ tab: t })}
          aria-current={t === active ? "page" : undefined}
          className={`rounded-full px-4 py-1.5 text-label font-bold transition-colors ${
            t === active
              ? "bg-surface-overlay text-ink-primary"
              : "bg-surface-raised text-ink-muted hover:text-ink-secondary"
          }`}
        >
          {LABEL[t]}
        </Link>
      ))}
    </nav>
  );
}
```

## Task 3: `BaselineTrendCard` — one tone prop instead of two colour strings

The single highest-leverage component on the surface: it renders up to **14 times on Trends and twice on Sleep**, and every call site passes two raw colour strings. Sixteen call sites × two hex literals is 32 of the app's unguarded colour literals in one file.

**The design decision, recorded here because there is no mockup to record it:** four tones, resolved to the existing chart tokens, assigned by what the metric measures.

| Tone         | Token     | Metrics                                                               |
| ------------ | --------- | --------------------------------------------------------------------- |
| `"cardiac"`  | `chart-1` | Resting HR · Blood oxygen · Respiratory rate · Sleeping HR            |
| `"recovery"` | `chart-2` | HRV · HRV (SDNN) · Readiness score · Sleep duration · Sleep score     |
| `"output"`   | `chart-3` | VO2max · Steps                                                        |
| `"body"`     | `chart-4` | Weight · BMI · Lean body mass · Waist · Wrist temperature · Hydration |

`chart-5` is deliberately unused: it is the "bad" tone in this app's tone map and none of these trends is a verdict.

**The second decision — the editorial cut the floor forces.** Four titles carry a `" vs baseline"` suffix. At `.label-micro`'s 12px/0.2em an uppercase `"RESTING HR VS BASELINE"` is ~225px of a 326px phone content width, and the reading beside it needs ~95px more. The band rect and its dashed centreline already say "against your baseline" on screen, and the `50 ±2` readout states it numerically, so **the visible suffix is cut from all four titles** — and preserved for assistive tech, which cannot see the band, by putting it in the SVG's accessible name. Nothing is claimed that was not claimed before; one channel gets shorter and the other gets longer.

```tsx
import { downsample } from "@/lib/charts";
import { TREND_STROKE, type TrendTone } from "./trend-tone";

interface Props {
  /** Micro label — "HRV". Never carries a " vs baseline" suffix; see below. */
  title: string;
  /** Series, oldest first; nulls are gaps, never zeroes. */
  values: (number | null)[];
  /** The athlete's own band, or null while baselines are calibrating. */
  band: { low: number; high: number } | null;
  /** What the metric measures; resolves to a chart token. */
  tone: TrendTone;
  unit: string;
  /** Decimals for the current reading; RHR and HRV are both whole numbers. */
  decimals?: number;
}

const VIEW_W = 300;
const VIEW_H = 90;

function polyline(
  values: (number | null)[],
  min: number,
  range: number
): string {
  const pts: string[] = [];
  const n = values.length;
  values.forEach((v, i) => {
    if (v == null) return;
    const x = n > 1 ? (i / (n - 1)) * VIEW_W : 0;
    const y = VIEW_H - ((v - min) / range) * VIEW_H;
    pts.push(`${x.toFixed(1)},${y.toFixed(1)}`);
  });
  return pts.join(" ");
}

/**
 * One trend against the athlete's own baseline band (1g). The band is a
 * translucent rect with a dashed centreline: the point isn't the absolute
 * number, it's whether today sits inside the athlete's normal range.
 *
 * Renders an honest empty state rather than a flat line when the range
 * holds fewer than two real readings.
 *
 * v0.99 slice 3 cut the visible " vs baseline" suffix four titles carried:
 * at the 12px floor an uppercase "RESTING HR VS BASELINE" plus its reading
 * overruns a phone's content width. The band rect and its centreline state
 * the comparison on screen and the ± readout states it numerically, so the
 * suffix was redundant for a sighted reader — and it moves into the SVG's
 * accessible name, which is the one channel that could not see the band.
 */
export function BaselineTrendCard({
  title,
  values,
  band,
  tone,
  unit,
  decimals = 0,
}: Props) {
  const series = downsample(values, 120);
  const nums = series.filter((v): v is number => v != null);
  const current = [...values].reverse().find((v) => v != null) ?? null;
  const stroke = TREND_STROKE[tone];

  return (
    <section className="glass mb-3 rounded-[18px] p-4">
      <div className="mb-3 flex flex-wrap items-baseline justify-between gap-x-3 gap-y-1">
        <h3 className="label-micro">{title}</h3>
        <p className="font-numeric text-label text-ink-muted">
          {current != null && (
            <>
              <span className="text-caption font-bold text-ink-primary">
                {current.toFixed(decimals)}
              </span>
              <span className="text-ink-muted">{unit}</span>
            </>
          )}
          {band && (
            <span className="ml-1.5">
              {current != null && "· "}
              {((band.low + band.high) / 2).toFixed(decimals)} ±
              {((band.high - band.low) / 2).toFixed(decimals)}
            </span>
          )}
        </p>
      </div>

      {nums.length < 2 ? (
        <p className="py-6 text-center text-caption text-ink-muted">
          Not enough readings in this range yet.
        </p>
      ) : (
        (() => {
          // The band has to fit inside the viewport too, or "inside your
          // normal range" would be drawn off-canvas.
          const lo = Math.min(...nums, band?.low ?? Infinity);
          const hi = Math.max(...nums, band?.high ?? -Infinity);
          const pad = (hi - lo) * 0.1 || 1;
          const min = lo - pad;
          const range = hi - lo + pad * 2;
          const yOf = (v: number) => VIEW_H - ((v - min) / range) * VIEW_H;
          return (
            <svg
              viewBox={`0 0 ${VIEW_W} ${VIEW_H}`}
              preserveAspectRatio="none"
              className="h-[90px] w-full"
              role="img"
              aria-label={`${title}${band ? " against your baseline" : ""}${current != null ? `, currently ${current.toFixed(decimals)}${unit}` : ""}`}
            >
              {band && (
                <>
                  {/* fill + fillOpacity rather than a second rgba() prop: one
                      token, one number, and no colour literal to go stale. */}
                  <rect
                    x="0"
                    y={yOf(band.high)}
                    width={VIEW_W}
                    height={Math.max(1, yOf(band.low) - yOf(band.high))}
                    fill={stroke}
                    fillOpacity="0.08"
                  />
                  <line
                    x1="0"
                    y1={yOf((band.low + band.high) / 2)}
                    x2={VIEW_W}
                    y2={yOf((band.low + band.high) / 2)}
                    stroke={stroke}
                    strokeOpacity="0.35"
                    strokeWidth="0.8"
                    strokeDasharray="3 3"
                  />
                </>
              )}
              <polyline
                points={polyline(series, min, range)}
                fill="none"
                stroke={stroke}
                strokeWidth="0.8"
                vectorEffect="non-scaling-stroke"
              />
            </svg>
          );
        })()
      )}
    </section>
  );
}
```

## Task 10: Labs — fold the two entry forms away

**The structural change.** Labs renders six blocks stacked, two of which are large always-open input forms: `HealthUpload` (paste box, file picker, extract button, and a five-column review table once an extraction lands) and `HealthManualEntry` (birth year, plus a four-field blood-pressure row). Together they are ~330 lines of form sitting between the reading content and the biomarker list, on a tab an athlete opens to **read** lab results and visits rarely to enter them.

**Owner decision, 2026-08-13: both fold behind the `Collapsible` primitive**, closed by default, below the reading content. Nothing is removed and no route changes — the same forms, one tap away, with the tab's actual subject first.

`HealthUpload` has a real constraint the fold must respect: it holds extraction state (`rows`) across a server action, and a mid-review athlete must not lose an extraction they have not saved.

**A correction, made during Task 7 and load-bearing here.** An earlier version of this paragraph said `CollapsiblePanel` keeps its children mounted and that Base UI hides rather than unmounts. **That is false.** Base UI's `useCollapsiblePanel` computes `shouldRender = keepMounted || hiddenUntilFound || mounted || open`, and with all of those falsy a closed panel renders `null` — its children are genuinely absent from the DOM and from `renderToString` output. Task 7 discovered this the expensive way: a test this plan wrote for the manual-vitals inputs was passing against markup that was never rendered at all.

The fold is still safe, but for a different reason, and the implementer needs the right one: **`rows` lives in `HealthUpload` itself, not in the panel's children.** The component stays mounted whatever the panel does, so closing the fold hides the review table without discarding it, and reopening restores it. What unmounts is the markup, not the state.

Two consequences to build to:

- **Still set `defaultOpen={rows !== null}`**, so an athlete who reopens the tab mid-review lands on their table rather than on a collapsed row. It only reads at mount, which is correct — the extraction form lives inside the panel, so `rows` can only go null → array while the panel is already open.
- **Any test you write for content inside a panel must open the panel first.** A `renderToString` assertion against a closed panel asserts over an empty string and passes vacuously. Use the client-render-and-click harness Task 7 added to `tests/journal-form.test.tsx` as the pattern, and give every such test a `toContain` sanity line naming something only the open panel renders.
