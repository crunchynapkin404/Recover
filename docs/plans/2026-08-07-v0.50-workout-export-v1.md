# v0.50 - Workout Export v1 - Implementation Plan

## Objective

Ship deterministic `.zwo` export from planned cycling sessions with strict TDD.

## Constraints

1. No migrations.
2. No device sync.
3. Pure export logic first, integration later.
4. Deterministic output required.

## Task plan (TDD)

## Task 1 - Core exporter contract

RED:

1. Add failing tests for `.zwo` root shape and required nodes.
2. Add failing tests for deterministic output equality.
3. Add failing tests for unsupported sport refusal.

GREEN:

1. Implement pure `sessionToZwo` exporter.
2. Implement deterministic type-to-template mapping.

REFACTOR:

1. Extract shared XML helpers if needed.
2. Keep public API stable.

Expected files:

- src/lib/workout-export/zwo.ts
- src/lib/workout-export/zwo.test.ts

## Task 2 - Week batch helper

RED:

1. Add failing tests for weekly export list behavior.

GREEN:

1. Implement `exportWeekToZwo` helper returning per-session outputs.

REFACTOR:

1. Keep sorting and naming deterministic.

Expected files:

- src/lib/workout-export/week.ts
- src/lib/workout-export/week.test.ts

## Task 3 - Tool surface (optional in v0.50 if time)

RED:

1. Add failing tool test for export preview payload.

GREEN:

1. Add read-only tool returning export preview and refusal reasons.

Expected files:

- src/lib/tools/get-workout-export-preview.ts
- src/lib/tools/get-workout-export-preview.test.ts
- src/lib/tools/registry.ts

## Verification gate

1. npm run lint
2. npm run typecheck
3. npm run test
4. npm run build

## Done criteria

1. `.zwo` export is deterministic and tested.
2. Unsupported sport is explicit and safe.
3. No planning logic changed.
