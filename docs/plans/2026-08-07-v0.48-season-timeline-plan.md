# Season Timeline (Target vs Actual) Implementation Plan

Goal: Ship a mobile-first Season tab in /train that visualizes weekly target load versus weekly actual load using existing week_plans and activities data.

Architecture: Add a new season tab to existing train URL state handling, implement a SeasonTab server component path in src/app/train/page.tsx, and add a focused chart component in components/train backed by a small chart-join helper in src/lib/charts.ts that aligns effective_target and weekly activity load by Monday weekStart.

Tech Stack: Next.js 16, React 19, TypeScript, Drizzle ORM, Vitest.

## Scope
- New Train tab: season.
- New /train season content with mobile-first timeline and compact stat row.
- Reuse existing weeklyActivitySummaries/weeklyLoads and existing schema fields.
- Add tests for URL state, data shaping, and season component rendering.

## Non-Goals
- No DB migration.
- No training-plan algorithm changes.
- No fitness/history chart rewrites.
- No predictive/future targets.

## Acceptance Criteria
1. /train has a working season tab with target vs actual timeline.
2. Data uses only week_plans.effective_target and activities.load weekly sums.
3. Mobile-first layout is readable at 375px width.
4. Existing train tabs continue to work unchanged.
5. Lint, typecheck, tests, and build all pass.

## Risks
- Sparse historical effective_target can reduce chart continuity.
- Local-time week alignment edge cases.
- Over-querying activities if date bounds are missed.
- UI crowding if too many weeks are displayed on small screens.

## Test Strategy
- Focused unit tests first (href + chart helper), then component render tests, then full suite.
- Keep deterministic fixtures with explicit weekStart dates.
- Include at least one test with null target and non-zero actual to avoid silent coercion bugs.

## Rollout Notes
- Safe additive release in /train.
- No data migration or background jobs.
- If real-world readability is poor on small phones, reduce default visible points from 16 to 12 without changing data contract.
