### The demand table was wrong, twice, and now says so

A refresh on 2026-08-24 was **misaligned by one row** — it read each card's
vote count from the row above — and tracked only the board's "In Review"
column. Every figure in it was wrong, and the derived claim that "Strength
overtook Calendar 121→155 vs 152→125" is wrong in its reasoning. What actually
happened: Strength 121→**125**, Calendar 152→**123**. Strength ended ahead by
two votes because Calendar collapsed, not by thirty because Strength surged.

The corrected table is in `docs/ROADMAP.md` with a note recording the error.
**Re-scrape with a structured per-card parse, not flattened page text** — the
cards render as `TITLE · category · comments · votes`, and flattening loses
which number belongs to which row.

**The one genuine remaining demand gap is narrow:** "Calendar" (123 votes)
splits into vacation-planning, which Recover already leads via availability
overrides, and **ICS export**, which is absent. It is under "Not scheduled".

## Traps and lessons found this session

- **A truncated full-page PNG is indistinguishable from a passing one.**
  `page.screenshot({fullPage:true})` snapshots whatever `scrollHeight` is at
  that instant, and surfaces that open animated containers (`.collapsible-panel`
  transitions height over 300ms) were photographed mid-animation. One soak run
  captured the same surface at 5217px in dark and 3649px in light. Fixed with
  `screenshotStable()`, which polls until the height settles. **The captures I
  opened as step-8 evidence during the v0.119.0 release were short, and I could
  not tell.**
- **Opening the pictures found two defects the whole suite missed.** Today
  rendered "14days" instead of "14 days" — a Next/SWC JSX-whitespace
  divergence where the standard `{" "}` fix is silently undone by
  `prettier --write` — and Today's first-run branch alone never passed `user`
  to `AppShell`. Step 8 works; use it.
- **A guard that refuses loudly is worth more than a green pipeline.**
  v0.120.0-rc.1's soak failed at Box 8 because the four new `first-run-*`
  surfaces met a demo account seeded _with_ data. That was the guard working.
  The PR's own CI passed, because `surfaces.yml` was wired correctly and
  `soak.yml` was not — and `soak.yml` only runs during a release.
- **`finish-release.yml` tags `main`'s HEAD, not the RC's commit.** So a fix
  merged between cutting an RC and finishing the release makes the tag point
  at code that was never in the promoted image. Cut a new RC instead.
- **Rollback has a hidden expiry.** `Promote` requires the target release's
  original Soak run id, so a rollback target is only reachable while that
  Actions run still exists. GitHub expires runs.

## Open gaps you are inheriting

- **`<Unavailable full>` silently discards `state.fix`.** Only its inline mode
  renders the link (`src/components/ui/unavailable.tsx:26-30`), so **three
  call sites now hand-render the link as a sibling**, each duplicating the

  documented at every site. This is the clearest follow-up v0.120.0 left.
- **The CTL drop for lifters has never been communicated** beyond the v0.119.0
  changelog entry. If Recover has users beyond its author, that deserves more.
- **`scripts/verify-surfaces.ts:359,589,1688` and
  `src/components/ui/segmented-tabs.tsx:17`** cite roadmap content by line
  number or section id (`2b.4`, `ROADMAP.md:581`) that now lives only in the
  archive. Left alone because the roadmap branch was documentation-only.
- **The destructive-migration rollback path is still untested.** The soak
  exercises a restore drill every release, so it is not untested in general —
  only untested under pressure against prod, which costs deliberately
  destroying production data to buy down.
- **No test pins that a `status: "error"`/`"revoked"` connection does not count
  as active** in `isFirstRun`. The predicate encodes it; nothing asserts it.

## What is next, and the one thing to decide first

**Phase 6 has three strands left**, each scoped as its own brainstorm → spec →
plan cycle rather than a checklist, because a UX phase written as a task list
becomes a tweak list:

- Information architecture — Today/Train/Coach/Body/Menu was set in v0.23.0
  and has had features bolted on since; Settings is long enough that a
  reviewer got lost in it.
- Flow and friction — confirm a week, plan a season, debrief a ride, connect a
  provider.
- Visual polish and motion.

**Before starting one, decide how much process it gets.** The
spec → plan → subagent-execution machinery used this session is built for
correctness work and earned its cost there — it caught three leaks in the
strength branch that twelve task reviews missed, and it caught a wrong demand
table. It is a poorer fit for visual judgment: you cannot spec a feel, and the
one thing that settled every UX question this session was building it,
screenshotting it, and looking. The first-run strand split the difference —
the spec was binding on the predicate gate and the capture coverage, and
explicitly not on wording or layout. That split is worth repeating.

**Phase 7 is the more interesting work and should still wait.**
`races.resultActivityId` records how every race actually went and nothing
reads it — the app has never checked a prediction against reality, which is
the one thing no competitor can do without the athlete's data. It is the
roadmap's own named opportunity. But it is a capability bet on an app whose
experience is still being examined, and Phase 6 was chosen as the maximum
focus deliberately.

## How to verify anything

**Everything CI runs:**

```bash
npm run lint && npm run typecheck && node scripts/migrate.mjs \
  && npm test && npm run format:check && npm run build
```

**With a database — do this before pushing, not after CI tells you:**

```bash
docker run -d --name scratch-db -e POSTGRES_USER=ci -e POSTGRES_PASSWORD=ci \
  -e POSTGRES_DB=ci -p 55432:5432 postgres:16-alpine
DATABASE_URL=postgres://ci:ci@localhost:55432/ci DATABASE_DRIVER=pg \
  node scripts/migrate.mjs
DATABASE_URL=postgres://ci:ci@localhost:55432/ci DATABASE_DRIVER=pg \
  ENCRYPTION_KEY=$(printf '0%.0s' {1..64}) \
  BETTER_AUTH_SECRET=0123456789abcdef0123456789abcdef0123456789abcdef \
  BETTER_AUTH_URL=http://localhost:3000 npx vitest run
```

Expect **2973 passed, 1 expected fail, 1 skipped**. Note that wiping a scratch
database needs `drop schema public cascade; drop schema drizzle cascade;` —
dropping only `public` leaves the migration journal behind, and
`migrate.mjs` will then report "migrations applied" against no tables.

**To see the first-run state:** create an owner with no wellness and no
connection (`scripts/seed-fresh-owner.ts`), sign in, and visit all four tabs.
It is also captured in CI now, by `surfaces.yml`'s `capture-first-run` job —
the first time a dataless account has ever been photographed.

**To release:** dispatch **Release RC** → **Soak** → **open the capture** →
**Promote** (with the soak's run id) → **Finish Release**. `docs/RELEASING.md`
is the one statement of the path and now carries the measured rollback numbers.
