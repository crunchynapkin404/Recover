v0.99 design reference — Train (largest surface)

Slice 0, Task 8. Train is 1,537 lines of src/app/train/page.tsx, four tabs (Week, History, Season, Fitness), and the densest surface in the app. This is the mockup that matters: the 12px floor does not fit Train's current content as shipped. This file shows what actually gets cut, stacked, truncated or moved to a drill-in to make it fit — and says plainly where nothing survives without restructuring.

The collision, measured

Train's current type ranges from 8px to 22px across src/app/train/page.tsx and src/components/train/* + src/components/week/*. A fresh grep against this checkout, for this task:

135
arbitrary text-[Npx] call sites under 13px
8px
smallest literal size found (Season timeline's per-bar session count)
261
ad-hoc *-white/[alpha] colour utilities (ink done as opacity, not tokens)
4
tabs sharing one 1,537-line page component

Most of that type promotes to the floor for free — short pills and single words just get a few more pixels of padding. Four spots genuinely collide with the floor because they pack fixed-width or fixed-height containers with as much text as the current tiny sizes allowed. Below is the full decision list; the four hardest ones — the week day row, the history row, the season timeline, and the fitness tiles — get their own worked examples afterward.

Every editorial decision

What Collides because Resolution Kind
Week day row — status pill A spelled-out uppercase pill ("completed" / "planned" / "missed" / "race", 9px today) needs ~90–110px at 12px bold tracked type — on a 380px row that also carries a weekday label and the workout text, two such pills (status + next-week's provisional badge) can exceed the row's width. Drop the spelled-out pill. Reuse the colour-dot convention week-strip.tsx already uses for this exact vocabulary — dot + sr-only text — instead of re-spelling status as a text pill. Cut
Week day row — height Weekday label, workout line and 1–2 sub-lines all need real line-height at 12–16px; the current row has no fixed height but was tuned for 9–12.5px content. Let the row grow (≈48px → ≈60–64px). Disclosed cost: a 7-day week runs ~90px taller; the rolling next-week preview is what actually gets cut back (see below), which mostly offsets it. Stack
Next-week preview — per-day rows Showing 7 more full rows (each provisional, each carrying its own "provisional"/"pinned" badge) roughly doubles the single most-visited tab's scroll length for data that is a forecast, not a commitment. Collapse to one summary row ("3 sessions planned, 2 open · 6.5h of 9h target") that expands into the full per-day list on demand. Committed (this week) data stays fully expanded; provisional data is the right thing to demote. Drill-in
History row — fixed height The row is a hardcoded 56px (h-14) tuned for a 12.5px name + 9.5px subline. Two lines of 12–14px text plus padding need more than 56px, so the fixed height either clips or forces vertical-centering to fight the text. Drop the fixed height in favour of a minimum height; the row sizes to its two lines of content (≈64–68px). No text or data is removed. Stack
History row — name / subline truncate was already doing real work at 12.5px; at 14–16px the same pixel width holds fewer characters before the ellipsis. Keep truncation as-is — it is the correct, existing behaviour. Disclosed cost: long activity names truncate a little sooner on narrow phones. Stack
History — sport filter / view tabs Pills grow ~20–30% wider at the floor. No cut needed — the row already scrolls horizontally (overflow-x-auto is in the source). Token promotion only. Already scrolls
Season timeline — per-bar labels 12 weekly columns, each with its own week label (9px) and session-count label (8px, the smallest text on the surface) stacked underneath. 12 independent 12px labels need roughly 500–540px of width — more than a phone viewport has, full stop. Cannot fit as shipped. Restructured: no per-bar labels; an axis tick only every 3rd week; a single "selected week" detail line below the chart replaces 24 always-on micro-labels with one always-legible readout. See the worked example below. Cannot fit
Season timeline — bar strip width Even without labels, 12 columns at a legible minimum bar width (~28–34px) plus gaps can exceed a narrow phone's viewport. The strip scrolls horizontally rather than compressing bar width below a legible minimum — same pattern as History's filter row. Scroll
Fitness tiles — label "Fitness · CTL" (13 characters) at 8.5px fits a ~110px tile column; the same string at 12px bold tracked type is as wide as the tile itself. Drop the redundant category word. Show "CTL" / "ATL" / "TSB" only — which is already exactly how pmc-chart.tsx's own inline legend labels these three values one panel below. The full name moves to an sr-only label; the chart's shared legend states it once instead of three times. Cut
Remaining-skeleton table Week / Phase / Target load at 9–11px fits a phone; "Target load" as a header word at 12px tracked uppercase, plus three columns' padding, can exceed 380px on the narrowest phones. The table gets its own horizontal-scroll container rather than shrinking columns below the floor. It stays a real table — the content (short numbers, one word) survives fine at 12–14px; only the container needs to scroll on the narrowest screens. Scroll
Bottom nav labels Shipped at 8px (text-[8px] in bottom-nav.tsx) — the same fix Today needed. Promoted to --text-label (12px). Icons keep their size; labels get more room beneath them. Promote
.label-micro global class A shared CSS class in globals.css hardcodes font-size: 10px. It backs several Train captions ("Why this week", "Last N weeks", form field labels) that this mockup promotes visually — but the class itself lives in src/, which this task does not touch. Flagged, not fixed here. Whoever implements the slice that first touches a .label-micro call site should retarget it to --text-label rather than leave a second, uncoordinated 10px floor in the codebase. Flagged
~261 ad-hoc opacity colours Ink done as white/NN alpha utilities rather than tokens — the exact class of low- contrast value the axe baseline (Task 7) measured across the app. Replaced by the 3-step ink ramp for every prose/label role, and --hairline for dividers/borders only. Status colour (emerald/amber/red/ violet) stays as accent, now sourced from the shipped --chart-* tokens. Cut
Race-day fuchsia Race rows use a literal text-fuchsia-300 — no fuchsia token exists in globals.css. This mockup substitutes the nearest shipped token (--chart-4, violet). If slice 2 wants race day visually distinct from every other build/ taper state, it needs its own token — not fixed here. Flagged
Colour, not just size. This task's brief is the type floor, but the two are entangled: most of Train's ~261 opacity utilities are the sub-12px captions above, so fixing size and fixing contrast happen in the same edit at almost every call site. Chart accent colours (--chart-1..5) were spot- checked against --surface-base and --surface-raised (4.4–9.2:1 in both themes) but two of the five dip to 3.9–4.4:1 against --surface-overlay in dark mode — avoided in this mockup for small text on that surface, not solved as a general rule. A full semantic-colour audit is out of scope here.
