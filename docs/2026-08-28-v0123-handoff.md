## Slice 3 is the availability drag-timeline

The spec section is `docs/specs/2026-08-27-week-surface-redesign-design.md`
under "The availability sheet (T)". The athlete chose it over two simpler
options, in these words: _"i want the flexibility of the block sheet but with
some kind of slider. easier."_

**The scaffolding is already built.** Slice 2 moved the existing availability
UI — `AvailabilityWeekSwitcher` and both `IntakeForm`s — wholesale into an
`availability` sheet, unchanged, precisely so this slice can replace their
innards without touching the page again. You should not need to edit
`src/app/train/page.tsx` at all beyond the sheet's contents.

**The model does not change.** `AvailabilityBlock` stays
`{ start, end, mins, energy, sports }`, days keep holding more than one block,
and every edit still commits through `validateBlocks`. This is a new _editor_
over an existing type.

**The two costs the spec names, and they are both real:**

1. **Touch targets.** Eighteen hours across a 390 px viewport is ~18 px per
   hour, so a one-hour block renders 18 px wide. The spec calls for a 44 px
   minimum rendered width, 15-minute snapping, and resize handles that appear
   only on the selected block. The distortion is deliberate and must be
   commented as such.
2. **A drag-only control is unusable by keyboard and screen reader.** Every
   block must be focusable with an accessible name ("Thursday 17:30 to 19:45,
   full gas") and arrow-key adjustment, with `BlockSheet`'s numeric editor kept
   as the precise path. **If the keyboard path is not done, the feature is not
   done** — and note that this session shipped three separate accessibility
   defects into work that was itself accessibility work.

## Traps this codebase will spring on you

Every one of these cost real time this session. They are listed in the order
you are most likely to hit them.

**Colour tokens that are equal to each other.**

- `--surface-raised` and `--surface-overlay` are **both `#ffffff` in light**.
  Anything resolving to `raised` (including `class="glass"`) is invisible
  inside a sheet, whose panel is `overlay`. Shipped four times before it was
  understood.
- `--surface-selected` **equals `--surface-base` in both themes**, by design.
  So `bg-surface-selected` is safe _only_ inside a raised/overlay container,
  never directly on the page. `PlanPreviewCard` renders in both contexts and
  needs its `variant` prop; every other component that carries the token is
  sheet-only.
- **`STATUS_DOT` owns colour in the day strip.** It is shared with
  `week-day-list.tsx` so a status never means two colours. Intensity gets a
  notch, never a hue.

**`BottomSheet` has five non-obvious behaviours, all load-bearing.**

- It sets `inert` on `[data-app-background]` itself, on mount. `AppShell` does
  **not** decide this — deriving it from the `overlay` prop's truthiness killed
  Today's entire page (an always-truthy `<SheetHost/>`) and then Coach's
  desktop page (a sheet that _mounts_ inside `lg:hidden`).
- It gates all of that on **`checkVisibility()`** — asked of the browser, not
  inferred from a prop or a mount. jsdom has no layout and no
  `checkVisibility`, so tests fall back to "mounted means visible".
- Its panel is **`tabIndex={0}`, not `-1`**. It is a scroll container, and with
  `-1` the one prose-only sheet ("Why this week", no buttons at all) failed
  axe's `scrollable-region-focusable` as serious — a keyboard user could not
  scroll it.
- Its Escape handler **defers to a nested `[role="dialog"]`**. `BlockSheet` is
  one, and without this Escape closed the outer sheet and silently discarded
  staged block edits.
- Its drag-to-dismiss only begins when the panel is **already scrolled to the
  top**, or long content cannot be read without the gesture that dismisses it.

**`BlockSheet` is `position: fixed`.** Per the CSS transforms spec, _any_
transform on an ancestor — including a zero one — makes that ancestor its
containing block. `BottomSheet` therefore omits its idle transform entirely;
restoring it collapses `BlockSheet` to a 132 px sliver. You will nest
`BlockSheet` inside the timeline sheet, so this matters directly.

**`plannedMins` (fill.ts) excludes strength.** It is the engine's _target_
minutes. Display code wants `displayMins` (day-shape.ts), which includes it —
otherwise a 90-minute strength day renders like a 5-minute one. A repo guard
(`tests/target-minutes-wiring.test.ts`) forbids hand-rolled sums and allowlists
the display one; read its comment before adding a third.

## How this codebase is worked, learned the expensive way

**Every defect of consequence lived at a seam.** Thirteen across the two
slices, each having passed its own task review: a shared component silently
restyling a different page; copy written as if the open day were today, after
another task made it usually not; a status branch reading emptiness instead of
the engine's intent, so a _missed_ session read as planned rest. Per-task
review structurally cannot see these. Budget for a whole-branch pass and point
it at the seams.

**Run mutations repeatedly, not once.** A guard test on a silent-data-loss path
passed **1 in 5** against the exact mutation it existed to catch, because it
asserted synchronously while the code under test fired inside
`setTimeout(fn, 0)`. A single mutation run called it green.

**Ask whether a claim holds for the app or only for the fixture.** "Zero
weekday labels outside the sheet" was true of a fixture that seeded no
availability and false of any real athlete, because `NextWeekSummary` renders
seven more rows when next week has availability. Seed the state you are
claiming about.

**The pipeline catches what the suite cannot.** Four defects reached the branch
with 3204 tests green: two found by the production capture at a desktop
breakpoint, one by the axe ratchet, one by opening the shipping bytes at step 8
(a surface photographing the Week tab under a name promising Season). **The
ratchet ceiling stayed at 0** — raising it is the easy move and the wrong one;
its own failure message tells you to open the artifact first, and doing that
named the rule, element and surface in one read.

**Commit as soon as you are green.** Seven implementers died mid-task on
account limits this session. One left a mutation applied in the working tree
(`{false ? (`) that had to be found by running the suite; another left five
tests red with one line missing. If you apply a mutation, restore it before
doing anything else.

## What you are inheriting

Named so they are not rediscovered as surprises.

- **There is no `ⓘ` anywhere in the app.** The spec puts the race-pacing prose
  behind one on the race chip, and the fuelling detail behind one in the open
  day. Neither exists; the content is reachable in the "Why this week" sheet but
  has no signpost from the thing it explains.
- **`SessionFuelling` and `RaceChip` are still full blocks on the page.** ~0.27
  of the 0.64 screens still between the surface and the spec's ~1.2 prediction.
  Both are already specified. Calling them "un-sheeted by design" would be
  false — they were slice 1's scope and slice 1 skipped them.
- **`BlockSheet` has no focus trap of its own.** While it is open the outer
  trap stands down, so Tab can walk into outer-sheet content it visually
  covers. Shipped deliberately; strictly better than before, when nothing had a
  trap at all.
- **`Math.round` vs anchors.** All three producers of "weeks until this race"
  now round down together, but `/train` anchors on `week.weekStart` while
  `previewTrainingPlan` anchors on `new Date()` — up to six days apart
  mid-week. Documented at `training-plan.ts`, not fixed.
- **The IA strand's parked question** — do Fitness, Sleep and Labs deserve to
  be tabs — is still parked on telemetry that now has real keys and little
  data.
- **`week-row.test.tsx`'s fixture is all empty days**, so it cannot distinguish
  the strip's two render modes. Give it a day with a workout when you next
  touch it.

## What is next, and why slice 3 is the right next thing

Slice 3 finishes the strand the athlete cares about most: they told us they
adjust availability **every single week**, which is why the standard week was
cut and the Sunday nudge exists. Availability editing is therefore the single
most-used write path in the app, and it is still a form with a modal per day.

After that, the honest order is: the `ⓘ` work and the two remaining blocks
(cheap, specified, closes the measurement gap), then Phase 6's fourth strand
(visual polish), then Phase 7 — where `docs/2026-08-27-structured-workouts-roadmap.md`
argues the real leverage is, and where `PlannedWorkout.exercises` already shows
the pattern for prescribing structure the engine can defend.
