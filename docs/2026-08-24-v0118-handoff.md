## What shipped this session

**v0.117.0 — closed a capture gap the previous handoff found the same day it
was written.** `docs/2026-08-20-pacing-capture-gap.md` documented that the
race-pacing line (v0.116.0) only renders for a _confirmed_ plan, and nothing
`surfaces.yml`/`soak.yml` ever seeded had confirmed one — a regression
deleting the line outright would have passed every gate. `scripts/seed-confirmed-race.ts`
and a new `train-race-pacing` surface close it. The fix required discovering,
by deliberately running the seed scripts in the wrong order and watching a
different surface fail, that `seed-confirmed-race.ts` **must** run before
`seed-two-race.ts` — `previewTrainingPlan` deletes every existing draft for
the user before writing its own, so the reverse order silently deletes the
two-arc draft `train-plan-preview` depends on.

**v0.118.0 — the demand map's 105-vote "Different FTPs indoor/outdoor" row,
closed as a fallback, not a feature.** Races have no indoor concept anywhere
in this app's model — a start line is always outdoors — so indoor FTP can
never mean "use it for race day." Its only honest role is a lower-confidence
anchor when outdoor FTP isn't set. `bodyPrefs.ftpWattsIndoor` sits beside the
existing `ftpWatts`; the fallback order is outdoor (athlete-set) → indoor
(athlete-set) → synced eFTP (derived) → refuse, threaded through
`resolveFtpAnchor()` (`src/lib/race/service.ts`), which also **replaced two
independently-drifting FTP resolutions** in `pacingAnchors()` and
`volume-inputs.ts` — the same shape of risk `raceCard()` was built to close in
v0.87. **Explicitly not historical load:** `training-load.ts` still divides
every past ride's power by one FTP — doing that correctly needs a per-activity
indoor/outdoor classifier that doesn't exist (Strava's own `VirtualRide`
signal is discarded at ingestion today). That's a real, separate, larger
project, named and left alone rather than silently punted.

Built via an 8-task subagent-driven-development plan (`docs/plans/2026-08-24-indoor-ftp.md`,
spec at `docs/specs/2026-08-24-indoor-ftp-design.md`): fresh implementer +
fresh reviewer per task, fix loops where reviews found real issues, then a
whole-branch review on the most capable model and one fix wave. Worth reading
if you're about to run this process yourself — two things it caught that a
faster pass would have missed:

- A triathlon's three-anchor confidence merge (`weakestOfTriathlonAnchors`,
  `src/lib/race/demand.ts:194`) had no test that actually drove it to land on
  "indoor" rather than "outdoor"/"synced" — the hardest logic in the whole
  change, and the gap was only caught because a task reviewer read the test
  list against the merge logic line by line, not because anything failed.
- The **same reviewer labeled that task "Approved" while still listing the
  gap above as an Important finding.** The label and the finding disagreed;
  treat the finding as binding regardless of the summary word next to it if
  you're driving this process yourself.

## Open gaps you are inheriting

- **The Settings summary chip ignores indoor-only FTP.**
  `src/app/settings/page.tsx:222` builds the collapsed "Body & app" summary
  from `bodyPrefsRow?.ftpWatts` only — an athlete who sets _only_ an indoor
  FTP gets no FTP mention in the chip, reading as unconfigured while the card
  underneath holds a value. Found and explicitly parked by this session's
  final review as outside the indoor-FTP plan's scope. Real, minor, one-line
  fix whenever someone's next in that file.
- **`export-import-drill.ts`'s `Carried<>` exhaustiveness type will surface
  again on the next `bodyPrefs` schema change.** `scripts/export-import-drill.ts:199`
  types its seed fixture as `Carried<typeof schema.bodyPrefs, "id">` — every
  column except `id` must be explicitly present. This session's schema
  addition broke that typecheck immediately, which is the point of the type,
  but it means **any** future `bodyPrefs` column needs that file (and
  probably `import-user.ts`'s field-by-field mapping) touched too, not just
  the schema file — plan for it rather than being surprised by it.
- **Triathlon and multi-day pacing refusals have still never been seen
  rendered.** Carried unchanged from the last handoff. Unit-tested, low risk,
  still not verified.
- **`scripts/repair-plan-sport.ts` still refuses two-race plans.** Carried
  unchanged, still names its own reason.

## Traps found this session

- **A git worktree with a symlinked `node_modules` breaks Turbopack's pinned
  `root`.** Two separate tasks this session hit `next dev`/`next build`
  failures in `.worktrees/v0117-indoor-ftp` because its `node_modules` was
  symlinked to the main checkout's for speed, and Turbopack's `root` pin
  (`next.config.ts`, see also `CONTRIBUTING.md`'s existing lockfile-root trap)
  rejects a symlink pointing outside it. Fixed both times with a real,
  gitignored `npm ci` inside the worktree. If you set up a worktree for
  speed, budget for a real install the first time anything touches `next
dev`/`next build`, not just `vitest`/`tsc`.
- **A task reviewer's overall verdict word and its listed findings can
  disagree.** See "What shipped this session" above — an "Approved" label sat
  next to an Important finding in the same report. The finding is what's
  binding; the label is not a shortcut past reading the findings list.
- **`Carried<T, K>`-typed fixtures are a compiler-enforced early-warning
  system for schema changes, and they will page you from files you didn't
  plan to touch.** See "Open gaps" above. Worth knowing before it happens
  rather than after.

## How to verify anything

**Everything CI runs:**

```bash
npm run lint && npm run typecheck && node scripts/migrate.mjs \
  && npm test && npm run format:check && npm run build
```

**With a database — do this before pushing, not after CI tells you:**

```bash
docker run -d --name scratch-db -e POSTGRES_USER=ci -e POSTGRES_PASSWORD=ci \
  -e POSTGRES_DB=ci -p 55432:5432 postgres:16-alpine
DATABASE_URL=postgres://ci:ci@localhost:55432/ci DATABASE_DRIVER=pg \
  node scripts/migrate.mjs
DATABASE_URL=postgres://ci:ci@localhost:55432/ci DATABASE_DRIVER=pg \
  ENCRYPTION_KEY=$(printf '0%.0s' {1..64}) \
  BETTER_AUTH_SECRET=0123456789abcdef0123456789abcdef0123456789abcdef \
  BETTER_AUTH_URL=http://localhost:3000 npx vitest run
```

Expect **2906 passed, 1 expected fail, 1 skipped** — not the 2895 the last
handoff cited. `docker rm -f scratch-db` after.

**To see the indoor-FTP fallback rendered:** seed a scratch database, set
only `ftpWattsIndoor` (not `ftpWatts`) on a `bodyPrefs` row via Settings or a
direct insert, confirm a race, and open `/train` — the race card's pacing
line should read low confidence with "Uses your indoor FTP — outdoor effort
may differ" in the assumption text.

**To release:** dispatch **Release RC** → **Soak** → open the capture →
**Promote** (with the soak's run id) → **Finish Release**. `docs/RELEASING.md`
is the one statement of the path, unchanged since the last handoff. Given
`main` is two versions ahead of the last tag, the version to cut is a live
decision — check whether v0.117.0 and v0.118.0 ship together as one release
or separately, and update `package.json`/CHANGELOG accordingly before
dispatching **Release RC**.
