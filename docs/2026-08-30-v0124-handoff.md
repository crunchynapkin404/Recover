## What shipped

The availability sheet's seven-rows-and-a-modal form became a week of
drag-editable time tracks. All geometry and mutation math is one pure module
(`src/lib/availability/timeline.ts`) with no React and no DOM; the component
over it owns input handling and nothing else. `IntakeForm` kept its form, its
hidden `blocks-${i}` inputs, its resync guard and its `PinnedAction` — only the
day list was replaced, and `tests/intake-form-resync.test.tsx` passes unedited,
which is the proof the submitted value did not move.

**Flow and friction is complete.** Three slices: composition, destinations,
and this. Train ▸ Week went 4.7 phone screens → 1.84 and stayed there.

## The number that went the wrong way, and why it stayed

The availability sheet's own choice load rose **17 → 31 controls** and its
length **0.84 → 1.09 screens**. Every day gained a `+` and an "edit precisely"
control. That is what direct manipulation costs.

A reduction to 24 was implemented and **reverted**. Moving "edit precisely"
onto the selected block is what the spec literally asks for, but on a Rest day
there is no block to select, so it made `BlockSheet` — the spec's own "precise
and assistive path" — unreachable. If you want that number down, the honest
lever is the `Pinned ×` badge: it is a _status_ that happens to be pressable,
up to seven of them, and a single week-level "back to standard" control with
the badge demoted to a non-interactive mark would cut six without removing any
capability. It would also fix the row crowding the captures show, where day,
summary, badge, `+` and edit share one line and the summary truncates.

## The lesson this release cost the most to learn

**Four defects reached a fully green pipeline and were caught by a human
looking at a picture.** Not by 3290 tests, not by a `0 confirmed` axe report
over 100 captured surfaces, not by lint or types.

- The pill's in-fill label rendered as `1h 00…` at every width the 44px touch
  floor produces.
- Adjacent pills physically **overlapped**, because a negative margin meant to
  bleed the track full-width was paired with padding that cancelled it exactly
  — the layout was computed for 342px against a real 306px.
- Every resize ended by unmounting the handles it was using, via the
  compatibility `click` browsers fire after a drag. **jsdom does not synthesise
  that click**, so no test in this repo could have caught it.
- **`rc.1` shipped a picture of nothing.** The availability capture showed
  seven empty tracks: `seedAvailabilityDefaults` wrote the standard week as
  untimed blocks (`start: null`), and the timeline correctly refuses to place a
  block with no position. Every athlete on the default path would have opened
  the feature to blank bars.

That last one is the one to internalise. It passed soak. It passed axe. It was
one screenshot away from production, and `docs/RELEASING.md` step 8 is the only
thing that stopped it — the step with no entry point, which exists for exactly
this and which `Promote` cannot verify you performed.

**Budget for opening the pictures. All of them, not the one you expect.**

## Traps this codebase will spring on you

The v0.123 handoff's list is all still true — colour tokens equal to each
other, `BottomSheet`'s five load-bearing behaviours, `BlockSheet` being
`position: fixed`, `plannedMins` vs `displayMins`. These are the new ones.

**`tests/viewport-zoom-guard.test.ts` matches BARE WORDS.** Naming
`touch-none` or `touch-pan-y` in a _comment_ counts as using it and fails the
guard. `block-sheet.tsx`'s scrim comment documents the same trap for the
offender ratchet. Write around the name.

**jsdom synthesises no click after pointer events.** Any behaviour that depends
on the compatibility click a browser fires at the end of a drag is invisible to
this suite. The timeline's `swallowClick` ref exists for that, and its first
test was vacuous because it exercised the handle path — which its own
`stopPropagation` already protects — rather than the pill path where the flag
matters.

**`NOMINAL_TRACK_PX` is a measured reference (338px at a 390px phone), not a
live measurement.** Positions are percentages of it. There is deliberately **no
CSS `min-width`**: a real container narrower than nominal is the one case a CSS
floor cannot absorb, and it renders as overlapping pills. If you change the
sheet's padding, the timeline's margins, or `IntakeForm`'s box, re-measure that
constant in a browser rather than deriving it.

**The engine seeds availability, not the seed scripts.**
`seedAvailabilityDefaults` in `src/lib/training-plan.ts` writes the standard
week on plan creation. Nothing in `scripts/` wrote availability at all until
`scripts/seed-availability.ts` was added this session — which the
`train-availability` capture surface now requires.

## What you are inheriting

Named so they are not rediscovered as surprises. The first four carry over
from v0.123 unchanged.

- **There is still no `ⓘ` anywhere in the app.** The spec puts race-pacing
  prose and fuelling detail behind one. Neither exists.
- **`SessionFuelling` and `RaceChip` are still full blocks on the page**, ~0.27
  of the remaining gap to the spec's ~1.2-screen prediction. Both specified,
  both skipped by slice 1.
- **`BlockSheet` has no focus trap of its own.** While it is open the outer
  trap stands down, so Tab can walk into outer-sheet content it visually
  covers.
- **`Math.round` vs anchors**: `/train` anchors "weeks until this race" on
  `week.weekStart` while `previewTrainingPlan` anchors on `new Date()` — up to
  six days apart mid-week. Documented at `training-plan.ts`, not fixed.
- **Two tests are recorded as vacuous**, deliberately kept rather than deleted.
  `withTimes` deriving `mins` from clamped clocks is unreachable now that
  `trackWindow` caps the window — it is labelled insurance, not protection.
  Both are commented beside the assertions.
- **Energy and sports are invisible on the timeline.** A block restricted to
  one sport looks identical to an open one, and energy reads only as fill
  density plus a notch count. `formatBlocks` prints neither. This matches what
  the old day list showed, so it is not a regression — but it is information
  the athlete entered and cannot see.
- **A drag holds a `committed` snapshot taken at pointerdown.** If
  `IntakeForm`'s server resync fires mid-gesture (it fires on unpin), the next
  pointermove commits from the stale snapshot. Narrow, unfixed, and cheap to
  reproduce only by unpinning while dragging.
- **The `Pinned ×` row is crowded** at 390px — day, summary, badge, `+` and
  edit on one line, with the summary truncating on a two-block day.
